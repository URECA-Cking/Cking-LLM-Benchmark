# 추천 입력 흐름 실험 계획

## 범위
태그 선택, 크리에이터 선택, 즐겨찾기 이력의 세 경로를 검증한다.
기존 v4 캐시로 입력을 고정하고 후보·블라인드 시트 생성 및 LLM 평가·집계를 완료했다. 세부 주제 분류와 계층 추천의 LLM 비교도 완료했다.
서비스 구현은 포함하지 않는다. 유료 분류·판정과 이슈 생성은 각각 사용자 승인 후 수행했으며, 커밋·푸시는 별도 명시 요청에 따라 진행한다.

## 결정
- 기존 real_eval을 바꾸지 않고 별도 flow_eval 모듈에서 캐시 검사를 재사용한다.
- 후보 생성까지 API 호출 없이 실행한다.
- 직접 선택 태그가 없으므로 cached LLM tag proxy로 명시한다.
- 실제 이력이 없으므로 synthetic favorite sets로 명시한다.
- popular baseline은 서비스 지표가 정해진 뒤 구현한다.
- v4에 기반한 추가 실험으로 기록하고 확정 채택을 주장하지 않는다.

## 순서
1. 원본 지문·dev/test·쿼리·합성 프로필 고정. 의존: v4 산출물.
2. 태그 경로와 seed 경로의 비교 후보 생성. 의존: 1.
3. 방법 이름 없는 사람 채점 시트 생성. 의존: 2.
4. 표본 수·채택 기준·채점 안내 확정과 독립 사람 채점. 의존: 3, 팀 결정.
5. 사람 점수 검증·집계·짝 차이·다양성·후보 부족 보고 구현. 의존: 4의 계약.
6. 서비스 직접 선택 태그·실제 이력·시간순 holdout 검증. 의존: 데이터 확보.

각 단계의 완료 조건과 확인 방법은 tasks/todo.md에 기록한다.

## 위험
- 정답으로 구성한 합성 취향은 현실 취향을 대변하지 않는다.
- 기존 분야 설명 평균 벡터는 실제 태그 쿼리 인코딩의 대리 입력이다.
- 같은 분야/크리에이터를 공유하는 입력의 CI를 독립 사용자 CI로 해석하지 않는다.
- 기존 설정을 재사용한 결과는 새 경로에서 최적화된 결과가 아니다.
- 서비스 태그 목록·인기 지표·선택 상한은 미확정이다.

## 세부 주제 후속 단계
- 정의와 경계 정본: docs/reference/creator-subtopics.md, data/creator-subtopics.json.
- 실험 계약과 실행: docs/experiments/subtopics/report.md.
- 형식은 이번 점수에 사용하지 않는다.
- 계층 M3의 임계값은 사전 고정 민감도이며 세부 정답 최적값으로 주장하지 않는다.
- LLM 태깅 승인과 새 추천 쌍 판정 승인을 분리해 추적한다.
