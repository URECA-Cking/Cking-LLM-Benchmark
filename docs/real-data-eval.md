# 실제 크리에이터 데이터로 M2·M3·M4 비교

합성 100명 결과([`embedding-method-selection.md`](embedding-method-selection.md))가 실제 소개글에서도 유지되는지 확인하는 실행 도구(`src/real_eval.py`, 이슈 [#28](https://github.com/URECA-Cking/Cking-LLM-Benchmark/issues/28))의 사용법과 사전 판정 기준이다. 실행 결과는 아래 [실행 결과](#실행-결과-2026-09-30) 절에 있다(이슈 [#14](https://github.com/URECA-Cking/Cking-LLM-Benchmark/issues/14)). **사람이 결정을 가르는 150쌍을 채점했고 일치율은 0.75로 사전 게이트(0.80)에 못 미쳤다(자세한 내용은 결과 절).**

## 왜 별도 도구인가
기존 `pipeline`은 합성 100명에 묶여 있다(데이터 해시 고정, 정확히 100명, 특정 ID 기반 대표 사례). 실데이터는 규모·분야 수·라벨 체계가 달라서 `similarity`·`tagging`·`metrics`·`judge`·`clients`는 재사용하고 실행 흐름만 새로 두었다. 기존 결과와 테스트는 바뀌지 않는다.

## 데이터와 취급 원칙
- 채널 소개글 원문과 정답 라벨은 **저장소에 커밋하지 않는다.** YouTube API 약관(저장 기간·재배포) 확인 전까지 외부 폴더에서만 읽고, 산출물은 `results/real/`(git 제외)에 쓴다.
- 외부 폴더는 `--data-dir` 또는 환경변수 `REAL_DATA_DIR`로 지정한다.

```
<데이터 폴더>/
├─ raw/pool.csv                 channel_id, name, bio, source_query   추천 후보 풀
└─ labels/
   ├─ gold_v2.csv               번호, gold_v2, use_gold, ...            정답 분야 (use_gold=1만 사용)
   ├─ reference_hidden.csv      번호, channel_id, ...                   번호 ↔ 채널 ID
   └─ categories_v2.csv         code, name, description                분야 목록(설명문은 zero-shot·LLM 태깅에 쓴다)
```
- 모델에 넣는 텍스트는 소개글이고, 소개글이 비어 있으면 채널명이다(서비스가 가진 정보만 쓴다. 구독자 수·영상 제목 등은 넣지 않는다). 분야 목록, 방식별 GPT 사용 여부, 평가 범위, 다음 실험(영상 제목·keywords 추가)은 [`real-data-scope.md`](real-data-scope.md)에 있다.

## 실행 순서
```bash
export REAL_DATA_DIR=<데이터 폴더>
python3 -m src.real_eval embed            # 후보 풀·분야 설명문 임베딩 (로컬 bge-m3 기본, --api로 DeepInfra). 4,743명 약 2분
python3 -m src.real_eval tag-llm          # 풀 전체 LLM 태깅 (분야 설명 포함 프롬프트, 동시 8개, 끊겨도 이어서)
python3 -m src.real_eval select-params    # dev/test 분할(분야별 층화)·tau·bonus 선택·쿼리 추출·test 태깅 정확도
python3 -m src.real_eval candidates       # 쿼리별 M2·M3·M4 상위 후보
python3 -m src.real_eval judge-sheet      # 방식별 상위 5의 합집합 = 판정할 쌍
python3 -m src.real_eval auto-judge       # LLM이 "추천에 넣을 만한가"(0/1) 판정
python3 -m src.real_eval human-sheet      # 무작위 150쌍 사람 채점 시트 (results/real/human_sheet.csv)
python3 -m src.real_eval human-agree      # 사람이 채운 시트와 LLM 판정의 일치율 (기준 80%)
python3 -m src.real_eval score            # 정밀도@5, M4 − M3 짝 차이, 사전 기준 판정
```

| 방식 | 유사도 |
| --- | --- |
| M2 | 소개글 벡터 코사인 |
| M3 | 코사인 + (zero-shot 태그가 하나라도 겹치면 +bonus_m3). 태그는 분야 설명문과의 코사인이 tau 이상이면 부여 |
| M4 | 코사인 + (LLM 태그가 하나라도 겹치면 +bonus_m4) |

- tau·bonus는 **dev 채널만**으로 고른다(정답 분야 기준). test 채널의 벡터·라벨이 바뀌어도 선택값이 같은지 테스트로 확인한다.
- 쿼리는 dev를 뺀 풀에서 무작위로 뽑는다: 일반(소개글 15자 이상) 300개, 짧은 소개글(15자 미만) 100개. 후보는 풀 전체(쿼리 자신 제외)에서 고른다.
- LLM 태깅 프롬프트에도 분야 설명문을 넣어 M3(설명문 임베딩)와 정보량을 맞췄다.

## 사전 판정 기준 (결과를 보기 전에 확정)
- **M4가 M3보다 정밀도@5가 +0.05 이상 높고, 쿼리별 짝 차이의 95% 신뢰구간(부트스트랩 2,000회)의 하한이 0보다 크면(구간이 0을 포함하지 않으면) M4를 채택하고, 아니면 M3를 채택한다.**
- 결정은 **일반 채널** 기준이다. 짧은 소개글 결과는 같은 규칙을 적용해 참고로만 함께 적는다.
- 정밀도@5는 쿼리의 상위 후보 5개 중 "추천에 넣을 만하다"(1)로 판정된 비율이다.
- 사람 150쌍과 LLM 판정의 일치율이 **80% 미만이면** 판정 기준을 고치고 사람 채점을 늘린 뒤 다시 판정한다.
- **채택은 이 사람 확인을 통과해야 "확정"이다.** `score`는 일치율 확인이 없거나, 미달이거나, 사람 채점이 아니거나(`--source claude`), 현재 판정·후보 쌍과 다른 입력에서 계산된 옛 결과면 채택을 **"잠정"** 으로 표시하고 경고한다. 일치율 결과에는 계산에 쓴 입력의 지문을 저장해 두고 `score`가 현재 입력과 맞는지 확인한다. 지문은 채점 표본뿐 아니라 **전체 평가 쌍의 판정 점수·텍스트 해시와 모든 쌍을 어느 방식이 뽑았는지(조합)** 를 함께 해시하므로, 표본은 그대로여도 후보 집합이나 표본 밖 판정이 바뀌면 이전 결과는 무시된다.

## 결정을 가르는 쌍의 확인·보정과 재판정 (결과를 본 뒤에 추가한 사후 분석)
사전 기준(위)은 바꾸지 않았다. 다만 무작위 150쌍의 64%는 M2·M3·M4가 모두 뽑은 쌍이라 M4 − M3와 무관했고, 실제로 둘을 가르는 쌍은 전체 2,425쌍 중 722쌍(30%)뿐이었다. 쿼리별 M4 − M3는 두 방식의 상위 후보 점수 차이라서 공통으로 뽑은 쌍은 상쇄되므로, 이 722쌍만 확인하면 된다. 그래서 아래 분석을 결과를 본 뒤에 추가했다. **모두 사후 분석이라 채택은 "잠정"이다.**

```bash
# 이번 결과의 사람 채점 150쌍은 다음 두 시트를 합친 것이다(같은 시드, 표본 ID는 명령으로 그대로 재생성된다).
python3 -m src.real_eval human-sheet --targeted --groups M4,M3 --n-each 50 --out human_sheet_targeted.csv           # M4만 50 + M3만 50
python3 -m src.real_eval human-sheet --targeted --groups M2+M4,M2+M3 --n-each 25 --out human_sheet_targeted_extra.csv  # M2+M4 25 + M2+M3 25
python3 -m src.real_eval human-agree --targeted --source human --file <시트1.csv>,<시트2.csv>   # 채운 시트(쉼표로 여러 개): 일치율, 조합별 채점 긍정률
python3 -m src.real_eval score --calibrated               # 채점 표본으로 보정한 정밀도@5와 M4 − M3
python3 -m src.real_eval rejudge                          # 722쌍을 더 큰 모델(gpt-5.5)로 다시 판정 (보정 없이 정확한 M4 − M3)
python3 -m src.real_eval score --rejudged                 # 재판정 결과로 M4 − M3
```
- **보정 방식.** 채점하지 않은 쌍의 점수를, 같은 방식 조합에서 LLM이 같은 판정(0/1)을 낸 표본 쌍에 사람이 준 긍정률로 바꾼다. 표본을 뽑지 않은 조합은 보정하지 않고, `score`가 보정 범위와 "조합 전체에 적용한 긍정률"을 함께 출력해 표본의 채점 긍정률과 어긋나지 않는지 볼 수 있다. (처음에는 이진 판정에 offset을 더하고 0~1로 잘라서, 이미 1인 쌍이 올라가지 못해 보고한 offset보다 적게 반영됐다. 리뷰에서 지적돼 고쳤다.)
- 보정한 **모든 조합**(M4만·M3만·M2+M4·M2+M3)의 긍정률이 각자 표준오차만큼 M4에 유리하게, 또는 불리하게 동시에 틀릴 때의 M4 − M3 범위도 함께 나온다(M4가 뽑은 조합은 +, M3가 뽑은 조합은 −). 이 범위는 조합별 긍정률의 불확실성만 반영하고, 채점자가 한 명이라는 점(채점자 간 차이)이나 채점자의 기대가 미친 영향은 반영하지 않는다.
- 이미 채점한 시트가 있으면 `human-sheet`는 덮어쓰기를 거부한다(`--out`으로 다른 이름을 쓰거나 `--force`). `score`와 `select-params`는 저장된 판정·LLM 태그가 현재 소개글과 모델·프롬프트로 만든 것이 아니면 중단하고 다시 실행할 단계를 알려준다. 후보(`candidates`)는 만들 때의 파라미터(tau·bonus·쿼리)·벡터 내용·LLM 태그 지문을 `candidates_meta.json`에 저장하고, 후속 단계(`score`·`human-sheet`·`human-agree`·`rejudge`)가 현재 원본 데이터(소개글·분야 설명문)로 임베딩·태그를 다시 검증한 뒤 이 지문과 대조한다(판정 쌍 밖 채널의 변경이나 벡터 재생성도 잡는다). 파라미터를 바꿨는데 `candidates`를 다시 안 하면 중단한다.
- `--source`로 채점 출처를 남긴다. 사람이 아니면(`claude`) `score`가 독립성이 약하다고 경고한다.

## 실행 결과 (2026-09-30)
**조건.** 후보 풀 4,743명(YouTube 채널), 정답이 있는 532명(dev 161 / test 371), 분야 17개, 임베딩은 로컬 bge-m3. 쿼리는 dev를 뺀 풀에서 일반 300개와 짧은 소개글 100개를 뽑았고 판정한 쌍은 2,425개다. 정답 라벨은 Claude가 붙이고 사람이 애매한 것과 무작위 표본만 검수했다.

**태깅 정확도 (test 371명).** zero-shot 태그 Top-1 0.722, Top-3 0.889(합성 데이터는 0.871, 1.000), LLM 태그 정답 포함률 0.908. 풀의 11.3%는 LLM이 분야를 못 정했다(UNCLASSIFIED).

**M4 − M3 (쿼리별 짝 차이, 부트스트랩 95% 구간).**
| 판정 방식 | 일반 300 | 짧은 소개글 100 | 사전 기준 적용 |
| --- | ---: | ---: | --- |
| **① gpt-5.4-mini (사전에 정한 판정기) — 공식 결과** | +0.041 [+0.028, +0.055] | +0.042 [+0.020, +0.066] | **M3** (+0.05 미달) |
| ② 다른 722쌍을 gpt-5.5로 재판정 (`rejudge`, 사후) | +0.063 [+0.045, +0.081] | +0.056 [+0.028, +0.088] | M4 |
| ③ 결정을 가르는 150쌍의 **사람 채점**으로 보정 (사후) | +0.074 [+0.059, +0.089] | +0.057 [+0.032, +0.086] | M4 |

③에서 보정한 네 조합의 긍정률이 모두 표준오차만큼 M4에 불리하게·유리하게 틀리면 일반 M4 − M3는 +0.053 ~ +0.093다(하한이 기준 +0.05에 거의 걸친다). 세 줄 모두 이 저장소 도구로 재현된다.

일반 채널의 방식별 정밀도@5(①)는 M2 0.601, M3 0.612, M4 0.653이다. 사후 비교로 M3 − M2는 +0.011 [+0.004, +0.018]이라 **zero-shot 태그 보정(M3)은 실데이터에서 임베딩 단독(M2)보다 거의 낫지 않았다.** 이득은 LLM 태그(M4)에서 나온다(M4 − M2 = +0.052).

**판정자와 사람의 차이.** 결정을 가르는 150쌍(네 조합 25~50쌍씩)을 사람이 채점했다(블라인드, 판정기와 같은 질문). 사람과 gpt-5.4-mini의 일치율은 **0.75(kappa 0.46)로 통과선 0.80에 못 미친다.** gpt-5.5도 0.77이라 게이트를 넘지 못한다. 방향은 일정하다. 두 판정기 모두 사람보다 박해서 사람 긍정률 0.43, gpt-5.4-mini 0.28이다. 조합별로는 M4만 뽑은 쌍이 사람 0.64 / mini 0.44(차이 +0.20 ± 0.08), M3만 뽑은 쌍이 0.40 / 0.24(+0.16 ± 0.06), M2+M4가 0.40 / 0.24(+0.16 ± 0.11), M2+M3가 0.08 / 0.08(0.00 ± 0.06)이다. 즉 mini는 M4만 뽑은 쌍에만 박한 것이 아니라 M3만·M2+M4 쌍에도 비슷하게 박하다. 그래도 M4 쪽 쌍이 더 많고(277 대 115) M4만 뽑은 쌍의 편차가 가장 커서 M4 − M3가 낮게 나온다.

**해석과 잠정 권고.** 사전 기준의 공식 결과(①)는 M3다. 사람 채점으로 보정한 ③은 일반 채널에서 +0.074 [+0.059, +0.089]로 M4를 가리키고, 판정기를 바꾼 ②(+0.063)도 같은 방향이다. 다만 사전 기준의 게이트(사람 일치율 ≥ 0.80)를 통과하지 못했으므로 사전 기준대로라면 판정 기준을 고치고 다시 판정해야 하며, ③·②는 사후 민감도 분석이라 채택은 **"잠정"** 이다. 그럼에도 서로 다른 세 근거(gpt-5.5 재판정, 사람 채점 보정, Claude 2차 판정)가 같은 방향이라 M4를 **잠정 권고**한다. 짧은 소개글은 ③에서 +0.057 [+0.032, +0.086]이다. 효과는 크지 않다. +0.06~+0.07은 추천 5개 중 "넣을 만한" 후보가 평균 0.3~0.4개 늘어나는 정도이고 상위 5개의 70~80%는 M3와 같다. M4는 새 크리에이터마다 LLM 호출이 필요하고(풀 4,743명 태깅 약 $1.2), 태그가 없는 쿼리(일반 8%, 짧은 소개글 33%)는 보정을 못 받는다. 태깅에 실패하면 M3(또는 M2)로 폴백한다.

**한계.**
- **사람 채점은 한 명(작성자)이 150쌍만 했다.** 결정을 가르는 722쌍 중 표본 150쌍이고 채점자가 한 명이라 채점자 간 일치는 알 수 없다. 판정기를 바꾼 것은 **결과를 본 뒤의 결정**이라 분석의 자유도가 있다. 사람 일치율 게이트(0.80)는 통과하지 못했다. 채점자가 이 저장소의 작성자라 M4 채택 방향에 대한 기대가 채점에 영향을 줬을 가능성도 배제할 수 없다(시트에는 어느 방식이 뽑았는지가 없다).
- gpt-5.5는 M4 태거(gpt-5.4-nano)와 같은 OpenAI 계열이라 자기 선호 편향 가능성이 있다. 사람 채점 보정이 같은 방향이라 이것만으로는 설명되지 않는다.
- 절대 정밀도 수치는 판정 기준(추천 목록에 넣을 만한가)에 따라 달라지는 값이고, 사용자가 실제로 좋아하는지는 서비스 지표로만 확인된다.
- 정답 라벨과 분야 목록(17개)은 수집한 채널을 본 뒤에 확장했고, 후보 풀은 검색어와 인기 동영상으로 모은 표본이다.

## 2026-09-30 진행 기록과 결론
**진행 순서.**
1. YouTube 채널 4,743개를 수집하고, 정답 라벨(17개 분야)은 Claude가 붙여 사람이 애매한 것과 무작위 표본만 검수했다.
2. 판정 기준(채택 규칙·일치율 게이트)을 결과를 보기 전에 [사전 판정 기준](#사전-판정-기준-결과를-보기-전에-확정)으로 확정했다.
3. 임베딩·태깅·후보 생성·자동 판정(gpt-5.4-mini) 전 단계를 실행했다(쌍 2,425개).
4. 결과를 본 뒤 M3·M4가 다르게 뽑은 722쌍만 결과를 가른다는 것을 확인하고 사후 분석을 추가했다: gpt-5.5 재판정, 조합별 표본 채점으로 보정.
5. 사람이 결정을 가르는 150쌍을 블라인드로 채점했다(작성자 1명, 조합별 M4만 50 · M3만 50 · M2+M4 25 · M2+M3 25). 처음에는 이 시트를 Claude가 채웠으나(독립성 약함) 사람 채점으로 대체했고, 그 과정에서 "mini가 M4만 뽑은 후보에 유독 박하다"는 초기 진단은 사람 채점으로 약해져 정정했다.
6. 외부 리뷰 2회(일치율 재사용 방지, 보정 방식, 옛 판정 캐시 혼입, 문서 정정)를 검증해 반영했다. 테스트 230개 통과.

**오늘 테스트의 결론.**
- **사전 기준의 공식 결과는 M3다.** M4 − M3 = +0.041 [+0.028, +0.055]로 기준(+0.05) 미달이다.
- **사람 채점으로 보정한 사후 분석은 M4를 가리킨다.** 일반 채널 +0.074 [+0.059, +0.089], 짧은 소개글 +0.057 [+0.032, +0.086]. gpt-5.5 재판정(+0.063)도 같은 방향이다.
- **다만 채택은 "잠정"이다.** 사람과 판정기의 일치율이 0.75(gpt-5.5는 0.77)로 사전 게이트(0.80)에 못 미쳤고, 보정은 사후 분석이며 채점자가 1명이다.
- **잠정 권고: M4(LLM 태그 보정).** 근거는 서로 다른 세 가지(gpt-5.5 재판정, 사람 채점 보정, Claude 2차 판정)가 같은 방향이라는 점이다. 효과는 작다(추천 5개 중 "넣을 만한" 후보가 평균 0.3~0.4개 증가, 상위 5개의 70~80%는 M3와 같음).
- **M3(zero-shot 태그 보정)는 M2(임베딩 단독) 대비 +0.011로 거의 이득이 없었다.** 이득은 LLM 태그(M4)에서 나온다(M4 − M2 = +0.052).
- **비용·운영:** M4는 새 크리에이터마다 LLM 호출이 필요하고(풀 4,743명 태깅 약 $1.2), 태그가 없는 쿼리는 보정을 못 받으므로 태깅 실패 시 M3(또는 M2)로 폴백한다.
- **확정하려면:** 사전 기준대로 판정 기준을 고쳐 재판정하고 사람 채점을 늘려 게이트(0.80)를 통과해야 한다. 이 결정은 팀에서 내린다.

## 해석할 때 주의
- 정답 라벨은 Claude가 붙이고 사람이 애매한 것과 무작위 표본만 검수했다. 분야 정확도는 "이 라벨 기준"이다.
- 분야 목록(17개)은 수집한 채널을 본 뒤에 확장했다. 분야 설명문이 데이터를 본 뒤에 쓰인 한계가 있다.
- 후보 풀은 검색어와 인기 동영상으로 모은 표본이라 검색어가 소개글에 그대로 들어 있는 채널이 많다.
- M4 태깅(gpt-5.4-nano)과 판정(gpt-5.4-mini)이 같은 계열이라 판정이 완전히 독립적이지 않다. 사람 150쌍 확인이 이를 점검한다.
- 이 결과는 소개글 텍스트 유사도의 경향이다. 사용자가 실제로 좋아하는지는 서비스 지표(클릭·응모 전환)로만 확인할 수 있다.
