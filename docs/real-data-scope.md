## 방식별로 GPT를 쓰는 곳
| 방식 | 임베딩 | GPT(LLM) |
| --- | --- | --- |
| M2 | bge-m3(로컬, 무료) | 사용 안 함 |
| M3 | bge-m3(로컬). 소개글과 분야 설명문의 코사인이 tau 이상이면 태그 | **사용 안 함** |
| M4 | bge-m3(로컬) | **사용함**: gpt-5.4-nano가 소개글을 읽고 분야를 고른다. 새 크리에이터마다 호출한다(풀 4,743명 약 $1.2) |

평가용 판정기(gpt-5.4-mini, 재판정 gpt-5.5)도 GPT지만 서비스에는 들어가지 않는다.

## 무엇을 평가했고 무엇을 안 했나
**평가한 것**
- 정밀도@5(추천 5개 중 "넣을 만한" 비율), 일반 300 · 짧은 소개글 100 쿼리
- M4 − M3 쿼리별 짝 차이와 부트스트랩 95% 구간
- 판정기와 사람의 일치율, 조합별 편향(사람 채점 150쌍)
- 태깅 정확도(정답 분야 기준)

**평가하지 않은 것**
- 재현율·순위 지표(NDCG 등). 판정한 것은 세 방식이 뽑은 상위 5개의 합집합뿐이라 뽑히지 않은 좋은 후보를 알 수 없다.
- 단순 기준선(무작위, 인기순, 같은 분야 무작위)과의 비교. M2가 실제로 유용한 수준인지의 바닥 기준이 없다.
- 실제 사용자 반응(클릭·팔로우 등), 추천 요청 지연·처리량.
- 서비스 크리에이터 데이터에서의 결과(이 실험은 YouTube 채널 기준).

## 정답 라벨 점검과 v3·v4 재실행 (2026-09-30, 사후 분석)
정답(gold_v2, 532개)을 분야 안내(`카테고리_안내_v2.txt`의 정의와 경계 기준)만으로 다시 확인했다. 정답 원문·채널별 라벨은 저장소에 두지 않으므로 여기에는 방법과 집계만 적는다.

**방법.** 라벨을 붙인 쪽과 다른 모델(gpt-5.5)이 안내문 그대로 채널 이름과 소개글만 보고 독립적으로 라벨을 다시 붙였고(`youtube-collect/scripts/audit_gold.py`), 기존 정답과 다른 것만 소개글을 읽고 안내 기준으로 판정했다.

**결과.** 532개 중 494개(92.9%)가 일치했고 38개가 불일치했다. 38개는 안내 기준상 변경 제안 17, 소개글에 분야 근거가 없어 제외 제안 6, 안내에 맞는 분야가 없어 판단 필요 3, 애매하지만 현재 라벨 유지 12로 나뉘었다. 불일치의 상당수는 **안내에 경계 규칙이 없어서** 생겼다(동물 영상 모음 대 반려동물, 야생동물, 코딩 교육 대 지식·교육).

**추가한 경계 규칙.** 직접 키우는 반려동물을 담은 채널은 PET, 여러 동물 영상을 모아 편집·해설한 채널과 동물 소재 애니메이션은 HUMOR, 야생동물은 KNOWLEDGE, 코딩 교육은 TECH. 분야 설명문(M3·M4 입력)은 바꾸지 않았다.

**v3 정답.** 위 규칙을 적용해 8개 라벨을 바꾼 정답을 만들었다(정답 채널 수는 532개로 같음).

**v4 정답(정답 정리 후 재실행).** 점검에서 나온 나머지 제안을 모두 결정해 반영했다. 규칙을 같은 방식으로 다른 채널에 적용한 7개와 안내의 경계 규칙에 어긋난 라벨 9개를 바꾸고, 소개글에 분야 근거가 없는 6개를 정답에서 뺐다. 법률 상담 1개는 OTHER로 바꿔야 하는데, OTHER·UNKNOWN은 기존 사전 기준대로 정답(tau·bonus 선택, 분야 정확도)에서 제외되므로 함께 뺐다. 결과적으로 v2 대비 **라벨 23개 변경 + 7개 제외, 정답 채널 525개**다. 안내에 딱 맞는 분야가 없거나 두 분야에 걸치는 3개는 현재 라벨을 유지했다. 사람이 검수한 라벨 2개도 안내의 명시 규칙(아이돌 이슈 소식은 NEWS, 연예인 팬 채널은 ENTERTAIN)에 맞춰 바꿨다. 

**v3로 다시 실행하는 법.** 정답 파일은 데이터 폴더의 `labels/gold_v2.csv`를 읽는다. 정답 버전별 사본은 수집 폴더의 `scripts/make_gold_variant.py <버전>`(예: `v4`)이 `gold_variants/<버전>/`에 만든다(저장소 밖). v3 파일을 그 이름으로 둔 데이터 폴더 사본(나머지는 원본으로 연결)을 만들고, 산출물 폴더는 `REAL_RESULTS_DIR`로 나눠 기존 결과를 덮어쓰지 않는다. **새 산출물 폴더는 비어 있으므로 `select-params`는 `embed.npz`와 `tags_llm.json`이 있어야 시작한다.** 소개글이 같으니 기존 캐시를 복사(필수)하고 `embed`·`tag-llm`을 실행해 캐시가 현재 데이터와 맞는지 확인한다(맞으면 호출 없이 끝난다). 캐시를 복사하지 않으면 두 단계가 처음부터 실행돼 시간과 비용이 든다(LLM 태깅 약 $1~2). 판정·재판정 캐시(`judgments*.json`)는 복사하면 새로 필요한 쌍만 호출하고, 복사하지 않아도 동작하지만 전체를 다시 판정한다.
```bash
export REAL_DATA_DIR=<v3 정답을 gold_v2.csv로 둔 데이터 폴더 사본> REAL_RESULTS_DIR=results/real_v3
mkdir -p results/real_v3 && cp results/real/{embed.npz,tags_llm.json,judgments.json,judgments_rejudge.json} results/real_v3/
python3 -m src.real_eval embed && python3 -m src.real_eval tag-llm            # 캐시 검증(복사했다면 호출 없음)
python3 -m src.real_eval select-params && python3 -m src.real_eval candidates && python3 -m src.real_eval judge-sheet
python3 -m src.real_eval auto-judge && python3 -m src.real_eval rejudge && python3 -m src.real_eval score --rejudged
```

**해석: 이 결과로 공식 결론(v2의 M3)을 바꾸지 않는다.**
- 라벨 8개(전체의 1.5%)를 바꿨을 뿐인데 공식 판정의 결론이 M3에서 M4로 뒤집혔다. 원인은 라벨이 더 정확해서가 아니라, dev/test 분할이 달라지면서 **M4 가산점이 0.2에서 0.3으로 바뀌고 평가 쿼리도 많이 바뀌었기 때문**이다(일반 쿼리 300개 중 기존과 겹치는 것은 72개, dev 161명 중 104명만 그대로). 두 값(+0.041, +0.059) 모두 채택 기준 +0.05 근처다.
- 태깅 정확도는 오히려 조금 낮아졌다(zero-shot Top-1 0.722 → 0.695, LLM 포함률 0.908 → 0.889). 표본이 371명이라 잡음 범위다.
- 결과를 본 뒤 정답을 바꿔 다시 돌린 사후 분석이므로 **사전 기준의 공식 결과는 v2의 M3로 유지하고**, v3는 "정답·분할 선택에 대한 민감도 확인"으로 기록한다. 방향(M4가 앞선다)은 사람 채점 보정, gpt-5.5 재판정, v3 세 곳에서 같지만, 채택 기준 근처의 값이라 공식 결론은 정답·분할 선택에 흔들린다.
- **v4는 정답 정리를 끝낸 뒤의 재실행이다.** 공식 판정이 +0.053으로 사전 기준(+0.05)을 넘었지만 기준을 0.003 넘긴 값이다. 같은 정답 정리 과정에서 +0.041, +0.059, +0.053으로 움직였으므로 공식 결과를 M4로 바꾸지 않는다. 안내 기준 위반과 근거 없는 라벨을 바로잡은 것이라 정당성은 있지만 결과를 본 뒤의 변경이라는 점은 그대로여서 **v2의 M3를 공식 결과로 유지하고 v4는 "정답 정리 후 재실행"으로 기록한다.** 방향(M4가 앞선다)은 사람 채점 보정(+0.074), v2 재판정(+0.063), v3, v4 모두에서 같고 크기는 +0.04~+0.08이다.
- 사람 채점 보정은 v2와 v4에만 있다. v3에는 없다. v4의 보정은 v2의 사람 채점을 재사용한 것이 아니라 v4의 결정을 가르는 쌍에서 새로 뽑아 채점한 150쌍으로 계산했다(쌍이 달라져 기존 150쌍 중 35쌍만 v4에 남아 있고, 재사용은 표본의 무작위성을 해칠 수 있어 하지 않았다).
- 정답을 바꿀 때마다 결론이 움직였으므로 정답 정리는 v4로 끝내고 이 정답에 사람 채점을 새로 붙였다. v4에서 결정을 가르는 쌍은 724개(M4만 311, M3만 74, M2+M4 51, M2+M3 288)이고 기존 사람 채점 150쌍 중 v4에 그대로 남은 쌍은 35개뿐이라 150쌍을 전부 새로 채점했다(재사용은 표본의 무작위성을 해칠 수 있어 하지 않았다).

| --- | ---: | ---: | ---: | ---: |
| M4만 뽑은 쌍 | 50 | 0.68 | 0.40 | +0.28 ± 0.06 |
| M3만 뽑은 쌍 | 50 | 0.26 | 0.12 | +0.14 ± 0.06 |
| M2+M4 | 25 | 0.20 | 0.12 | +0.08 ± 0.08 |

- 일치율은 0.77(kappa 0.49)로 통과선 0.80에 못 미쳤다(gpt-5.5는 0.81). 사전 기준대로면 판정 기준을 고치고 다시 판정해야 하며, 채택은 **"잠정"** 이다.
- gpt-5.4-mini는 모든 조합에서 사람보다 박했다. v2 사람 채점에서는 M4만(+0.20)과 M3만(+0.16)의 편차가 비슷했지만 v4에서는 M4만이 M3만의 두 배(+0.28 대 +0.14)다. M4만 뽑은 쌍이 311개로 가장 많아서 공식 판정이 M4 − M3를 낮게 잡고, 보정하면 +0.053이 +0.071로 올라간다. 다만 두 편차의 차이(0.14)는 표준오차(약 0.085)의 1.7배 정도라 확정적이지 않다.
- 보정 결과는 일반 채널 +0.071 [+0.054, +0.087], 짧은 소개글 +0.056 [+0.033, +0.081]로 둘 다 M4 쪽이다. 조합별 긍정률이 표준오차만큼 M4에 불리하게 틀리면 +0.045까지 내려가 기준(+0.05) 아래다.
- `score`가 "사람 채점 일치율을 확인하지 않았다"고 경고하는 것은 무작위 표본(`human_agree.json`) 기준이라, 결정을 가르는 표본만 채점한 v4에서도 나온다. v4의 사람 채점 결과는 `human_agree_targeted.json`에 있다.
- 채점자가 한 명이고 사람 채점은 사후 분석이며, 일치율 게이트(0.80)를 통과하지 못했다. 공식 결과는 계속 v2의 M3다.

표본은 아래 명령으로 그대로 재생성된다.
```bash
export REAL_DATA_DIR=<v4 정답을 gold_v2.csv로 둔 데이터 폴더 사본> REAL_RESULTS_DIR=results/real_v4
python3 -m src.real_eval human-sheet --targeted --groups M4,M3 --n-each 50 --out human_sheet_targeted.csv           # M4만 50 + M3만 50
python3 -m src.real_eval human-sheet --targeted --groups M2+M4,M2+M3 --n-each 25 --out human_sheet_targeted_extra.csv  # M2+M4 25 + M2+M3 25
python3 -m src.real_eval human-agree --targeted --source human --file <시트1.csv>,<시트2.csv>
python3 -m src.real_eval score --calibrated --rejudged
```

소개글이 짧은 채널(쿼리의 33%가 태그를 못 받음)과 LLM이 분야를 못 정한 채널(11%)을 개선할 수 있는지 본다. 현재 모델 입력은 소개글(없으면 채널명)뿐이다.

**이미 받아 둔 데이터.** `raw/channels_raw.csv`, `raw/channels_more.csv`(5,128채널)에 `keywords`(2,875채널), `country`, `uploads_playlist`가 있다. 평가 풀 4,743채널 중 `keywords`가 있는 채널은 2,681개이고, 소개글이 짧은 채널 957개 중에서는 236개(25%)뿐이라 `keywords`만으로는 짧은 소개글 문제가 크게 줄지 않는다. 데이터 수집 폴더(`youtube-collect/`, **이 저장소 밖**)의 `scripts/build_pool_extra.py`가 이를 `raw/pool_extra.csv`(channel_id, country, keywords)로 만든다(API 호출 없음). 2026-09-30에 실행해 4,743채널(keywords 있음 2,681)이 나오는 것을 확인했다.

**새로 받을 데이터.** 같은 폴더의 `scripts/collect_videos.py`가 채널별 최근 영상 20개의 제목·설명을 `raw/videos.jsonl`에 모은다(`playlistItems.list`, 채널당 1 quota, 전체 약 4,743). 원문은 로컬 전용이다. **수집은 끝났다:** 2026-09-30에 `raw/videos.jsonl`에 평가 풀 4,743채널이 모두 들어 있다(영상 20개를 채운 채널 3,589개, 평균 17.0개, 영상이 없는 채널 42개). 제목 총 80,487개에 빈 제목과 삭제·비공개 표시는 없었다. 영상이 없는 채널은 비공개·삭제된 재생목록으로 추정하지만 원인은 확인하지 못했다. 두 스크립트와 그 결과를 읽는 `real_eval` 코드는 이 저장소에 아직 없으며, 다음 실험을 시작할 때 별도 이슈·PR로 추가한다.

**비교 조건과 절차.** (A) 소개글만(현재 결과), (B) 소개글 + `keywords`, (C) 소개글 + `keywords` + 영상 제목 20개. 결과를 보기 전에 사전 기준(M4 − M3 ≥ +0.05, 구간 하한 > 0)을 적어 두고 조건별로 임베딩·태깅·판정을 다시 한다. 결과를 가르는 쌍이 새로 생기면 사람 채점 표본을 다시 뽑는다.
