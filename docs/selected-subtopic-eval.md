# 직접 선택 세부 태그 비교

## 목적과 현재 상태

기존 H4는 크리에이터 소개에서 추정한 세부 태그를 입력으로 사용했다.
이번 비교는 사용자가 직접 고른 관심 주제에 적절한 후보를 추천하는지 확인한다.
PR #35의 소개글 최종 평가와 별도 진단이며 기존100개·801쌍 결과나 설정을 바꾸지 않는다.

**사람 평가 완료:** 성집이 선택한7개 관심 입력·중복 제거53쌍을 모두 평가했다.
평균 P@5는0.714→0.800이나 개선은 베이킹1개 입력에 집중됐다. 신규 API 호출0.

## 입력

| 사용자의 선택 | 기존 taxonomy 대응 |
| --- | --- |
| 헬스 | FITNESS_WEIGHTS: 웨이트 |
| 코딩 | TECH_PROGRAMMING: 프로그래밍 |
| 베이킹 | FOOD_BAKING |
| 헤어 | BEAUTY_HAIR |
| 신발 | FASHION_SHOES |
| 가방 | FASHION_BAGS |
| 국내 여행 | TRAVEL_DOMESTIC |

한 번에 여러 관심사를 섞지 않고 각 세부 태그를 별도 입력으로 비교한다.
관심사는1명이 직접 선택했으며 독립 사용자7명의 표본으로 해석하지 않는다.
헬스는 웨이트로 범위를 좁힌 대응이다. 같은 FASHION 분야의 신발·가방도 있어 독립 분야7개의 비교가 아니다.

## 비교 조건

| 조건 | 검색 입력과 보정 |
| --- | --- |
| 상위 분야만 사용 | 상위 분야 설명 벡터로 검색 + 후보의 LLM 상위 분야 일치 시0.2 |
| 직접 세부 태그 반영 | 동일 벡터 검색 + 상위 분야 일치0.1 + 세부 태그도 일치하면0.1 추가 |

후보 풀4,743명, 소개글·벡터·상위/세부 태그 캐시, 동점ID 정렬, 상위5명을 동일하게 사용한다.
세부 조건의 최대 가산점도0.2로 유지한다. 세부 정보가 없거나 주제가 다르면 상위 일치0.1만 준다.
세부 임베딩으로 검색 입력까지 바꾸지 않는다. 이번은 직접 선택 주제의 순위 보정 규칙 전체 비교다.
세부 입력의 모든 활용법이나 H4의 서비스 우월성을 검증하는 실험이 아니다.

후보 세부 태그는 기존 LLM 분류다. 크리에이터가 직접 선택한 태그 데이터는 없다.
평가자는 후보 태그·방법·순위를 보지 않고 선택한 주제와 소개글만 보고 판단한다.
1 적절 / 0 부적절 / U 판단 어려움. 두 조건 모두 동일 세부 관심사에 대한 적합성으로 채점한다.
U는 적절성 미확인으로 계산하고 별도 비율을 기록한다.

## 준비 진단

전체85개 taxonomy 입력:632쌍,72개 입력의 상위5명 순서 변경,5개 주제의 태그후보5명미만.
이는 실제 선택85개가 아니라 코드로 열거한 합성 진단이다.

직접 선택7개 입력:53쌍,7개 모두 순서 변경,태그후보5명미만인주제0개.
순서변경과 태그일치 증가는 정확도 증거가 아니다. 태그 기반 방식에 유리한 대리 지표다.
태그 누락·오분류 때문에 실제 사람 적합성이 낮을 수 있다.

## 평가와 집계

    cd ~/Desktop/Cking-LLM-Benchmark
    .venv/bin/python -m src.human_check_cli recommendations \
      --experiment-dir results/selected_subtopics_user_v1 --limit 53 \
      --output results/selected_subtopics_user_v1/human_review.json

q로 중단하고 같은 명령으로 재개한다. 최종801쌍 채점 파일과 섞지 않는다.
53쌍 완료 후 내용·후보·답변 계약을 검증하고 주제별 P@5·U 비율·차이와7개 관심사의 기술 평균을 보고한다.
1인의 작고 상관된 관심사 표본이므로 모집단 우월성 구간이나 확정 채택 기준을 적용하지 않는다.
유망하면 실제 사용자 선택 데이터를 늘려 후속 평가한다.

원문·개별 답은 로컬 results에 보관한다. 공개 준비 집계는 data/selected-subtopic-preparation.json이다.
사람 평가 결과는 아래와 같다. 모든 분야나 실제 사용자 일반화를 입증한 것으로 표현하지 않는다.

실행 검증: Python3.12 전체290 passed in 6.24s, CLI53개·완료0개 확인, 신규 API 호출0.

**결론:** 직접 세부 선택은 베이킹처럼 큰 분야만으로 의도를 좁히기 어려운 입력에서 도움이 될 가능성이 관찰됐다.
M4를 기본으로 유지하고 선택사항으로 세부 관심사를 받는 제품안은 검토할 근거가 생겼다.
다만 1명·7개 관심사 중1개 개선이며 전체 사용자 정확도 향상이나 최적 보정값을 확정한 결과가 아니다.
기존 크리에이터 기반 H4의 추가 효과가 불명확했던 결론과 모순되지 않는다. 입력과 평가 목표가 다르다.
크리에이터가 직접 등록한 세부 태그, 여러 관심사 동시 선택, 추천 전환율은 이번에도 미검증이다.
상위 분야만 쓰는 조건도 동일 세부 관심사에 대해 평가했으며, 일반 분야 추천 품질 평가와 구분한다.
