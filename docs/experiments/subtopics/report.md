# 세부 태그 추천 실험: 조건과 상세 결과

빠른 결론과 핵심 표는 [결과 요약](../../history/recommendation-exploration.md)을 먼저 읽는다. 이 문서는 고정 조건·실행 방법·전체 민감도 결과를 설명한다.

## 범위

정의 데이터는 `data/creator-subtopics.json`, 사람이 읽는 정의·경계는 `docs/creator-subtopics.md`다.
17개 상위 분야를 유지하고 85개 세부 주제와 10개 콘텐츠 형식을 분리한다.
형식은 정의만 만들고 이번 분류·추천 점수에는 사용하지 않는다.

## 고정 조건

기존 flow_m234_v4의 입력 468개·후보 풀 4,743개·dev/test·소개글·임베딩·상위 태그·집계 규칙을 유지한다.
M2·기존 M3·기존 M4를 기준선으로 두고 계층 M3/H3, 계층 M4/H4를 비교한다.
세부 주제 미분류는 기존 상위 태그 보정으로 폴백한다. 태그 불일치만으로 후보를 제거하지 않는다.
태그 선택 입력은 아직 상위 태그만 선택하므로 세부 주제 입력을 만들어 넣지 않는다. 이 경로는 폴백으로 기존 결과와 같다.
세부 관심사 선택 화면 자체의 효과를 측정하려면 별도의 고정 입력 표본이 필요하다.

## M3 세부 분류

- 기존 M3 상위 태그와 tau를 유지한다.
- 각 상위 분야 안에서 소개글과 가장 가까운 세부 주제를 하나 선택하고, 임계값 미달은 미분류 처리한다.
- 임계값 0.35·0.45·0.55는 사전에 기록한 민감도 조건이다. 세부 정답 라벨로 선택한 최적값이 아니다.
- 정의·포함·제외 예시를 같은 로컬 bge-m3로 임베딩한다. 원래 채널 벡터는 재생성하지 않는다.
- 로컬 모델 캐시만 사용한다. API 임베딩은 이번에 호출하지 않는다.

## M4 세부 분류

- 기존 M4 상위 태그를 유지하고, 그 상위 태그 아래의 세부 주제만 허용한다.
- 상위 태그가 있는 4,205개 소개글만 gpt-5.4-nano-2026-03-17로 분류하고 538개는 호출하지 않는다.
- 최대 3개 고유 주제를 허용하고, 근거가 부족하면 빈 목록을 반환하도록 모델에 지시한다. 각 태그에 모델이 선택한 원문 구절을 기록한다.
- 중복 코드는 인용 출처와 허용 부모를 먼저 검증한 뒤 한 번만 반영하고 원래 응답을 보존한다.
- 인용 후보는 원문을 행별 최대 240자로 자른 연속 문자열이다. 모델이 ID를 선택하면 로컬에서 원문으로 변환한다.
- 초기 저장 결과 일부는 자유 인용 또는 원문 enum으로 생성됐다. 모두 인용 문자열의 원문 포함 검사를 통과했지만 근거 선택 정책이 섞인 탐색 실행이라는 한계를 기록한다.
- 재개 시 저장 결과를 검증하고 유효 결과는 재호출하지 않는다. 검증 실패와 HTTP 429에는 3회 제한 재시도를 적용한다. 동시 호출은 4개이며 재시도 후 실패하면 미분류로 숨기지 않고 중단한다.

선택 ID를 원문으로 변환한 뒤 포함 여부를 검사하므로, ID 방식에서 이 검사는 주제의 의미적 타당성을 검증하지 않는다. 선택 구절이 주제를 뒷받침하는지는 미검증이며 사람 검증이 필요하다.

## 점수

같은 상위 분야에서 양쪽 모두 세부 분류된 경우:

- 상위만 일치: 기존 가산점의 0.5배.
- 세부도 일치: 상위 0.5배 + 세부 1.0배(주 비교) 또는 세부 0.5배(총량 유지 민감도).
- 한쪽이라도 세부 미분류: 기존 가산점 그대로.

여러 상위 분야는 가장 큰 보정 하나를 쓰며, 즐겨찾기는 seed별 보정 점수 중 최대를 취한다.
주 비교 H3의 임계값은 0.45, 세부 가중치는 1.0으로 고정한다. 나머지 조건은 민감도 분석으로 모두 보고하며 평가 결과로 최적 조건을 고르지 않는다.

## 검증과 한계

정의 완전성, 주제/형식 분리, 인용 출처·부모 제한, 미분류 폴백, 임계값, 벡터/스칼라 보정 일치를 테스트한다.
태그 정의만으로 품질이 좋아졌다고 주장하지 않는다. 후보 변경 후 같은 판정 질문으로 P@5와 입력별 짝 차이를 비교해야 한다.
세부 정답 라벨·직접 선택 태그·사람 일치율·실제 즐겨찾기·실사용자 반응은 미검증이다.
상위 오분류를 그대로 물려받는다. 세부 주제가 입력에 드러나지 않는 경우를 진단에서 별도로 보고한다.
초기 공급자 호출 중 저장되지 않은 실패 응답 사용량은 일부 미기록이며 실제 청구액은 미확인이다.

## 실행 현황

4,205개 분류를 모두 완료했으며 상위 태그가 없는 538개는 호출하지 않았다.
세부 주제 할당은 전체 풀 중 3,932개, 미할당은 811개(호출 제외 538개 포함)다. 이는 정확도 지표가 아니다.
저장된 분류 호출 사용량은 입력 2,918,895·출력 156,437토큰이며 일부 초기 실패 호출은 포함되지 않는다.
468개 입력·11개 조건의 후보 합집합은 3,709쌍이다. 기존 판정 2,801쌍을 재사용하고 신규 908쌍을 별도 승인받아 평가한다.
분류 완료 당시 테스트: `273 passed in 5.09s`. 후속 검증 기록은 [검증 문서](../../history/recommendation-validation.md)에 구분한다.

### H4−M4: 세부 LLM 태그 보정의 차이

2,000회 입력 단위 짝 부트스트랩 95% 구간이다. 합성 입력·탐색 비교의 구간이며 실제 사용자 효과를 보장하지 않는다.

| 경로 | 차이 | 95% 구간 |
| --- | ---:| --- |
| 태그 1개 | 0.000 | [0.000, 0.000] |
| 태그 2개 | 0.000 | [0.000, 0.000] |
| 일반 소개글 | 0.023 | [0.011, 0.035] |
| 짧은 소개글 | 0.016 | [0.000, 0.032] |
| 같은 분야 즐겨찾기 | 0.082 | [-0.012, 0.200] |
| 여러 분야 즐겨찾기 | 0.035 | [-0.035, 0.129] |

일반 소개글 경로는 개선 구간이 0보다 크다. 짧은 소개글·즐겨찾기의 구간은 0을 포함한다.
태그 경로는 상위 태그 입력만 유지했으므로 결과가 같으며 세부 태그 선택 UI 효과는 검증하지 않았다.

### H3−M3: 세부 임베딩 태그 보정의 차이

주 조건(임계값 0.45·세부 가중치 1.0)의 같은 입력 단위 탐색 95% 구간이다.
