# 가입·즐겨찾기 흐름의 추천 실험

## 목적과 상태
- 신규 사용자: 관심 태그 또는 좋아하는 크리에이터 선택. 건너뛰면 인기순.
- 신규 크리에이터: 소개글 작성과 직접 태그 선택.
- 기존 사용자: 즐겨찾기한 크리에이터를 입력으로 별도 페이지에서 추천.
- 두 온보딩 입력을 동시에 받는지는 미확정. 현재는 각각 평가한다.
- 서비스 코드 구현이 아닌 오프라인 실험이다. 1차 LLM 보조 평가를 완료했으며 사람 평가는 미검증이다.

## 데이터와 고정 계약
`real_v4`의 원본·임베딩·LLM 태그·params를 읽고 기존 최신성 검사를 재사용한다.
`prepare`는 dev/test ID, 기존 일반·짧은 소개글 쿼리, 후보 풀·정답·분야 설명·벡터·태그·params의 지문을 고정한다.
`candidates`는 같은 원본과 계획인지 재확인하고, 달라졌으면 새 결과 폴더를 요구한다.
시드만 고정하지 않고 입력 ID 자체를 저장한다. 짧은 소개글 그룹도 기존 분류를 유지한다.
원문·채널별 라벨·결과·채점 시트는 `results/` 안에만 저장하고 커밋하지 않는다.

**한계:** 기존 LLM 태그는 직접 선택한 태그의 대리 입력이다. 자기 선택 태그의 효과를 검증한 것이 아니다.
정답 v4는 즐겨찾기 묶음을 구성할 때만 이용하며 후보 점수에는 쓰지 않는다.
이 묶음은 실제 사용자의 즐겨찾기 이력이 아니다. 기존 v4는 이미 관찰한 표본이므로 추가 탐색 분석이다.
새 표본과 서비스 데이터로 최종 검증해야 한다.

## 입력 표본
| 경로 | 고정 입력 |
| --- | --- |
| 태그 | 분야별 단일 태그, 모든 두 태그 조합 |
| 크리에이터 | 기존 v4 일반·짧은 소개글 쿼리, 한 명씩 선택 |
| 즐겨찾기 | test 라벨로 같은 분야 3명, 분야 목록에서 인접한 두 분야의 각 1명 |

즐겨찾기는 dev 채널을 제외한다. 인접 분야 조합은 초기 탐색용 부분 표본이다.
많은 즐겨찾기·시간 가중치·정보 부족 그룹·실제 사용자 이력은 후속 단계다.

## 비교 방법
| 경로 | 방법 |
| --- | --- |
| 공통 | 고정 시드 무작위 기준선 |
| 태그 | 태그 겹침 개수 순(동점 무작위), 분야 설명 평균 임베딩, 태그가 겹치는 후보의 임베딩 순 |
| 크리에이터·즐겨찾기 | seed별 최대 코사인, 정규화한 평균 벡터 코사인, seed별 순위 투표(RRF), 최대 코사인+태그 보정 |

태그 경로는 설명문 벡터를 재사용한 대리 쿼리다. 실제 입력 문자열을 새로 인코딩한 결과와 구분한다.
최대 코사인은 즐겨찾기 중 적어도 하나와 가까운 후보를 고른다.
RRF는 각 seed의 순위 r에 1/(60+r)을 더해 seed 수로 나눈다. 60은 초기 탐색 설정이며 튜닝된 값이 아니다.
태그 보정 bonus는 v4 M4 값을 고정해 재사용하며 새 경로에서 최적이라고 주장하지 않는다.
모든 seed는 모든 방식의 후보에서 제외하고, 점수 동점은 채널 ID로 정한다.
태그 필터에 후보가 적으면 목록을 그대로 짧게 반환한다. 인기순 보충은 아직 적용하지 않는다.
서비스 태그 목록·인기 지표가 확정되면 해당 조건을 별도 계획으로 추가한다.

## 평가와 후속 단계
- 질문: 이 관심 태그 또는 선택한 크리에이터를 좋아하는 사용자에게 이 후보를 추천할 만한가? 0/1.
- 같은 입력·후보 쌍은 한 번 채점해 방식 간 재사용한다. 방법 이름을 보여주지 않는다.
- 현재 모듈은 전체 합집합 시트까지 생성한다. 사람에게 전체를 채점하게 하는 것은 기본 요구가 아니다.
- 채점 전에 경로·그룹별 표본 수와 평가 입력 부분집합을 고정한다. 선택 입력에서는 비교 방식의 후보 합집합 전체를 채점한다.
- 입력별 P@5는 관련 후보 수/5로 계산해 후보 부족도 반영한다. 반환 개수도 별도로 보고한다.
- 같은 입력에 대한 방식별 P@5 짝 차이와 입력 단위 부트스트랩 95% 구간을 계산한다.
- 여러 태그·즐겨찾기는 관심 분야별 반영 정도를 보조 지표로 본다. 분야 정보도 대리 입력이라는 한계를 표시한다.
- 경로·그룹별 결과를 따로 보고한다. 서로 연관된 입력 조합과 합성 프로필은 독립 사용자 표본이 아니다.
- AI가 채운 점수를 사람 평가로 기록하지 않는다. 가능한 경우 둘 이상의 독립 채점자를 둔다.
- 기존 M4-M3 >= 0.05 규칙은 이번 방법 비교에 자동 적용하지 않는다. 채택 기준은 채점 전에 확정한다.
- 인기 지표 확정, 직접 선택 태그 확보, 새 평가 표본, 사람 평가·집계 도구는 남은 작업이다.

## 1차 보조 평가 실행 (2026-10-01)
`src.flow_experiment`는 후보를 재계산해 저장 내용과 대조하고, 아래 평가 표본을 점수 확인 전에 고정한다.
- 태그 1개: 17개 모두.
- 태그 2개: 136개 중 고정 시드로 뽑은 17개.
- 즐겨찾기: 같은 분야 17개·서로 다른 분야 17개 모두.
- 위 68개 입력의 후보 합집합 1,032쌍은 gpt-5.4-mini-2026-03-17로 새로 평가한다.
- 크리에이터 1명: 400개 중 모든 비무작위 방법의 판정이 기존 캐시에 있는 385개(일반 298·짧은 소개글 87)만 기존 공식 판정으로 비교한다. 나머지 15개는 누락 판정을 0으로 처리하지 않고 제외한다. 크리에이터 경로 무작위 기준선은 판정하지 않았다.
- 사람 시트는 빈 상태로 유지하고 LLM 점수는 별도 JSON에 저장한다.

cd ~/Desktop/Cking-LLM-Benchmark

`--judge`가 없으면 로컬 진단과 기존 판정 재사용만 한다. 최초 준비도 신규 판정도 평가 계약을 기록한다.
계약이 같으면 실패 후 재실행 시 저장한 신규 판정을 재사용한다. 키는 환경에서 읽고 출력하지 않는다.
`evaluation_plan.json`, `llm_judgments.json`, `summary.json`은 output-dir에 저장한다.

**해석 제한**
- 신규 태그·즐겨찾기 질문과 기존 단일 크리에이터 질문은 다르므로 경로 간 절대 P@5를 비교하지 않는다.
- 태그 경로에서는 관심 분야 중 하나에 부합하면 관련, 여러 즐겨찾기에서는 적어도 하나와 실제 방향이 이어지면 관련이다. 두 관심사를 모두 반영하는지는 별도 지표다.
- 분야 반영 진단은 후보의 LLM 태그와 선택 분야를 대조한 값이다. 태그를 사용하는 방법에 유리한 지표이며 사람 관련도·독립 정확도가 아니다.
- 짝 차이 CI는 고정된 입력을 재표집한 탐색 구간이다. 서로 관심 분야·채널이 겹치므로 독립 사용자 표본의 CI가 아니다.
- 단일 크리에이터 385개는 완전 판정 가능한 부분집합이라 누락으로 인한 선택 편향 가능성이 있다.
- 후보 태깅과 판정 모두 같은 제공자 계열이다. 사람 일치율은 이번 실험에서 확인하지 않았다.
- 자동 판정 결과만으로 채택 확정을 하지 않는다. 실제 청구액도 미확인이다.

### 관심 분야 반영 진단과 잠정 해석

- 전체 두 태그 조합 136개에서 두 분야 모두 노출한 비율: 태그 겹침 순 99.3%, 임베딩 66.9%, 태그 필터+임베딩 73.5%. 이는 LLM 품질 평가의 17개 부분집합과 다른 표본이다.
- 다른 분야 즐겨찾기 17개에서 두 분야 모두 노출한 비율: 최대 유사도 47.1%, 평균 벡터 58.8%, 순위 합산 76.5%, 최대 유사도+태그 보정 52.9%.
- 모든 입력·방법에서 후보 5개 미만인 경우는 0개였다. 선택/즐겨찾기 대상 제외와 후보 중복 없음도 확인했다.
- 태그 선택은 필터+임베딩을 다음 사람 평가 후보로 권고한다. 두 태그의 균형 노출은 별도 배분 규칙 검증이 필요하다.
- 즐겨찾기는 최대 유사도+태그 보정을 다음 평가 후보로 권고한다. 순위 합산은 분야 균형은 더 좋지만 이번 관련도는 낮아 기본안으로 확정하지 않는다.
- 다른 분야 즐겨찾기에서 태그 보정과 최대 유사도의 차이 구간은 0을 포함한다. 단독 최대 유사도보다 확실히 낫다고 주장하지 않는다.
- 신규 API 토큰 사용량: 입력 492,104·출력 12,858. 판정 호출 구간 약 241초. 청구액 미확인.
- 새 판정은 1,032쌍 모두 완료했다. 실행·집계 도구를 포함한 전체 테스트도 검증한다. 사람 채점·실사용자 반응·인기순 비교는 미검증이다.
