# v2/v4 재분석과 v5 재구현 — 2026-10-14

최종 `grounded-detail-candidates-v5-compact`는 첫 시도·최종 49/50, 중복 오류 0회였다.
v4와 공통 성공한 48개에서 세부 누락 10→10·과잉 4→2·F1 0.816→0.838이었다.
상위 지표는 소폭 악화됐으며 총 세부 누락 감소는 확인하지 못했다. 기본값 v2를 유지한다.

최초 v5는 정의 보존·중복 금지 지침을 추가했지만 실제 모델은 이를 안정적으로 따르지 않았다.
이번에는 v2/v4/최초 v5의 원본 요청·응답·revision과 AI 기준을 다시 대조한 뒤,
지침만 변경한 두 수정본과 코드별 고정 슬롯의 별도 스키마 실험으로 구분해 구현했다.
기존 버전의 API는 재호출하지 않았다. 과거 프롬프트 바이트·기준·시도·revision은 보존한다.

## 고정 슬롯 구현과 비교 원칙

새 `grounded-detail-candidates-v5-code-map`는 모든 상위·세부 코드에 nullable 객체 슬롯 하나를 둔다.
선택된 슬롯의 근거를 기존 배열 후보로 일대일 변환하고, 원본 객체도 별도 보존한다.
모델이 별도의 code/parent 문자열을 작성하지 않아 동일 코드의 다중 객체와 잘못된 부모 선택을
출력 구조에서 줄인다. 중복 JSON 키는 명시적으로 거부한다. 근거·부모를 고치거나 후보를 삭제하지 않는다.
`_rank`의 정확한 인용·빈 근거·중복·부모 관계 검증과 `detail-limit-v2` 정책은 그대로 적용한다.

각 세부 슬롯의 스키마 description은 해당 taxonomy 정의·include·exclude를 포함한다.
이 변경은 프롬프트와 출력 스키마를 함께 바꾼 **별도 구조 실험**이며 지침 하나의 기여 효과를 분리한 비교가 아니다.
기본 비교기는 스키마 차이를 계속 거부하고 `--schema-experiment`에서만 명시적으로 비교한다.
모델·입력·taxonomy·정책·온도·SDK 재시도·timeout·시도 상한·AI 기준 출처/해시는 고정한다.

최종 구조 실험은 사용자의 추가 승인을 별도로 받고 최대 150회로 실행한다.
실제 결과와 사용량은 아래에 추가하며, 독립 사람 정답·독립 홀드아웃·팀 채택 검증은 이번 개발 실험에 포함하지 않는다.

평면 고정 슬롯의 첫 실제 실행은 58회, 첫 시도 46/50·최종 47/50이었다.
중복 오류는 0회였지만 성공 출력 중 미분류가 24개로 늘었다. v4와 공통 성공한 46개에서
세부 누락 9→18, 과잉 4→1, F1 0.812→0.667로, 과잉은 줄었지만 누락이 악화됐다.
이 결과도 성공으로 처리하지 않았다. 이어서 상위를 먼저 선택한 뒤 그 아래 세부 슬롯만
판단하는 계층 구조를 구현했다. 기존 평면 슬롯과 이름·프롬프트·스키마·원본 기록을 구분한다.
계층 슬롯 실행은 같은 추가 승인 150회 중 평면 슬롯 58회를 제외한 최대 92회로 제한했다.

계층 슬롯은 실제 55회로 첫 시도 47/50·최종 48/50, 중복·부모·core 인용 오류 0회였다.
그러나 v4와 공통 성공한 47개에서 세부 누락은 9→15, 과잉은 4→3, 세부 F1은 0.817→0.719였다.
상위 F1은 0.881→0.930으로 개선됐지만 세부 누락이 해결됐다고 표시하지 않는다.

요청 사용량에서 반복 스키마의 부담도 확인했다. 계층 스키마는 55,958자로,
평면/계층 요청의 입력 토큰은 각각 평균 약 25,446/25,877이었다.
기존 v4는 평균 약 7,838 입력 토큰이었다. 문맥 길이가 정확도 저하의 원인이라고 단정할 수는 없지만,
같은 근거 객체와 taxonomy 설명이 반복된다는 구현상 부담은 직접 확인했다.
따라서 검증 형태가 같은 `$defs/$ref` 공유 스키마를 추가했고 프롬프트 바이트는 바꾸지 않았다.
새 스키마는 14,866자로 73.4% 줄었으며, taxonomy 전체는 프롬프트에 그대로 유지한다.
스키마 annotation의 반복도 줄었으므로 단순한 토큰 수만의 인과 효과를 입증한 실험이라고 해석하지 않는다.
