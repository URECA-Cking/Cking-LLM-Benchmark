# 임베딩 모델·추천 방식 선택 근거

## 결론

**임베딩 모델은 `bge-m3`, 유사도 방식은 M4(임베딩 + LLM 태그 보정)를 1순위 후보로 제안한다. 다만 이것을 확정 채택으로 발표하지는 않는다.** E1(태깅 정확도)·E2(관련도)·E3(대표 사례) 세 지표 모두에서 `bge-m3`가 `text-embedding-3-small`을 일관되게 앞섰고, `bge-m3` 안에서는 M4가 관련도에서 가장 높았다. E3에서는 M2가 경품 잡음(X01)에 걸리는 반면 M3·M4는 통과해, 태그 보정이 실제로 잡음에 강하다는 근거가 됐다(아래 E3 절 참고). 다만 M3와 M4의 E2 차이는 신뢰구간이 겹칠 만큼 크지 않아, 외부 LLM 의존을 줄이고 싶다면 M3도 근거 있는 대안이다. 100명 규모 합성 데이터의 경향 확인이며, 실제 운영 규모 재검증 전까지는 결과를 확정 성능으로 보지 않는다.

> **2026-09-28 재검증**: 외부 코드 리뷰로 발견된 6개 문제(dev/test 라벨 누수, 판정시트 덮어쓰기, 캐시 과장, spot-check 편향, 경품잡음 미검증, Windows 해시 실패)를 모두 수정하고 파이프라인을 재실행했다. 아래 수치는 전부 수정 후 값이다. 헤드라인 결론(`bge-m3` + M4가 1순위)은 수정 전후로 바뀌지 않았지만, 근거의 질이 달라졌다 — 특히 dev/test 누수가 있던 tau·bonus로도 같은 결론이 나왔던 것이 우연이 아니었음을, 누수를 막은 뒤에도 같은 결론이 재현되며 확인했다. 자세한 수정 내역은 본문 각주와 [issue #4](https://github.com/URECA-Cking/Cking-LLM-Benchmark/issues/4)를 참고.

## 측정 조건

- 데이터: `data/creators.csv` 100명(dev 30 / test 70), 쿼리 30명. `data/categories.csv` 10개
- 비교 대상: 임베딩 2종(`text-embedding-3-small`, `bge-m3`) × 방식 4~5종(M1~M4, 참고 R1·R2) = 11개 설정
- tau·bonus는 dev로만 그리드서치, 성적은 test로 계산 (`src/pipeline.py select-params`)
- 실행: 2026-09-28, `python3 -m src.pipeline embed / tag-llm / select-params / candidates / judge-sheet / auto-judge / score-judgments / report / spot-check / spot-check-report`

## E1. zero-shot 태깅 정확도 (test 70명)

| 지표 | text-embedding-3-small | bge-m3 |
| --- | ---: | ---: |
| tau | 0.2707 | 0.4801 |
| Top-1 정확도 | 0.729 | **0.871** |
| Top-3 포함률 | 0.886 | **1.000** |

bge-m3는 test 70명 전원이 상위 3개 안에 정답 분야를 포함했다.

## E2. 관련도 (LLM 자동 판정, 쿼리 30명 × 상위 5명, 556쌍)

| 설정 | 관련도@5 | 95% CI | nDCG@5 | 무관비율@5 |
| --- | ---: | --- | ---: | ---: |
| R1 (분야만, 기준선) | 0.273 | [0.17, 0.37] | 0.311 | 0.753 |
| M1_openai | 0.147 | [0.06, 0.24] | 0.146 | 0.867 |
| M2_openai | 0.287 | [0.18, 0.39] | 0.339 | 0.773 |
| M3_openai | 0.267 | [0.17, 0.36] | 0.294 | 0.773 |
| M4_openai | 0.407 | [0.26, 0.57] | 0.469 | 0.667 |
| R2_openai | 0.367 | [0.23, 0.49] | 0.406 | 0.680 |
| M1_bge-m3 | 0.260 | [0.15, 0.37] | 0.266 | 0.773 |
| M2_bge-m3 | 0.393 | [0.26, 0.52] | 0.454 | 0.680 |
| M3_bge-m3 | 0.447 | [0.31, 0.59] | 0.524 | 0.627 |
| **M4_bge-m3** | **0.493** | [0.34, 0.65] | **0.560** | **0.580** |
| R2_bge-m3 | 0.447 | [0.30, 0.59] | 0.492 | 0.620 |

판정은 사람이 아니라 **LLM 자동 판정**(`gpt-5.4-mini`, 556쌍, 비용 약 $0.14)으로 계산했다. M4 태깅에 쓴 모델(`gpt-5.4-nano`)보다 강한 모델을 판정에 써서, 같은 LLM이 자기 태깅을 스스로 좋게 채점하는 순환 편향을 줄였다.

**신뢰도 검증(spot-check)**: 처음 구현한 spot-check는 M4를 baseline들의 **합집합**과 비교해, "M4=A, M3=B, R2=A"처럼 다른 baseline이 우연히 같은 후보를 가지면 실제 차이를 놓치는 편향이 있었다(리뷰로 발견, 수정 후 회귀 테스트 추가). M4 vs M3, M4 vs R2를 각각 **양쪽 차집합**으로 직접 비교하도록 고치자 불일치 쌍이 12쌍에서 **141쌍**으로 늘었다 — 그만큼 처음 버전이 M4의 우위를 뒷받침하는 근거를 실제보다 좁게 보고 있었다는 뜻이다. 141쌍 전부를 사람이 보기엔 부담이 커서, 고정 시드로 무작위 **30쌍**을 뽑아 사람이 직접 재판정했다. 완전 일치율 0.80, ±1 이내 일치율 1.00으로 극단적 불일치(2점 차)는 없었다.

## E3. 대표 사례 (top-5, 11개 설정 전체, `src/pipeline.py report`)

| 설정 | 통과 | 실패 사례 |
| --- | ---: | --- |
| M1_openai | 3/7 | X12↔K03, X13↔S01, X14→K07, X15→F06 |
| M2_openai | 5/7 | X12↔K03, X14→K07 |
| M3_openai | 5/7 | X12↔K03, X14→K07 |
| M4_openai | 6/7 | X14→K07 |
| R2_openai | 5/7 | X14→K07, X15→F06 |
| R1 (분야만) | 5/7 | X14→K07, X15→F06 |
| M1_bge-m3 | 4/7 | X12↔K03, X14→K07, X15→F06 |
| M2_bge-m3 | 6/7 | X01 (경품잡음, 게임 크리에이터 G09 섞여 들어옴) |
| **M3_bge-m3** | **7/7** | 없음 |
| **M4_bge-m3** | **7/7** | 없음 |
| R2_bge-m3 | 5/7 | X14→K07, X15→F06 |

"분야 넘기" 사례(X14, X15)는 입력 분야(declared) 기반 방식(R1, R2)에서만 계속 실패한다. declared 보정은 정의상 분야를 넘는 유사성을 찾지 못하므로 당연한 결과다. openai 임베딩은 X14→K07(요리 크리에이터의 유사 목록에 여행 크리에이터가 들어가야 하는 사례)에서 모든 방식이 약했고, bge-m3만 이를 풀었다.

**경품 잡음(X01·X02) 테스트는 리뷰 전까지 실제로는 검증되지 않고 있었다.** `Creator.input_text()`는 `bio`가 있으면 `events`를 아예 안 쓰는데, X01·X02는 경품 문구가 `events`에만 있고 `bio`는 따로 있어서 모델이 경품 문구를 한 번도 본 적이 없었다(리뷰로 발견). `bio`에 경품 문구를 직접 넣어 재검증하자 **M2_bge-m3(순수 임베딩)는 X01에서 "닌텐도 스위치" 문구에 끌려 무관한 게임 크리에이터(G09)를 상위 5명에 포함시켜 실패**했고, M3·M4(태그 보정 적용)는 여전히 통과했다. 태그 보정이 경품 잡음에 실제로 강하다는 것을 보여주는 첫 근거다.

## 선택 이유와 한계

- **bge-m3를 고른 이유**: E1·E2·E3 세 지표 모두에서 격차가 뚜렷했다. 특히 E1 Top-3 포함률 1.000과 E3 전체 통과는 우연이라 보기 어렵다.
- **M4를 1순위로 하되 M3를 대안으로 남기는 이유**: E3는 M3·M4가 동률(7/7, M2는 경품잡음 실패로 탈락)이라 이것만으로는 못 가른다. E2에서 M4가 M3보다 관련도 0.046 높았고, 95% 신뢰구간이 겹치긴 하지만([0.34, 0.65] vs [0.31, 0.59]) 방향은 일관됐다. M4를 쓰려면 **운영 중에도 LLM 태깅 파이프라인(비용·지연·장애 대응)을 유지해야 한다** — 이 운영 비용이 부담되면 M3(zero-shot 태그, 외부 LLM 불필요)로도 충분히 근거 있는 대안이다.
- **한계**:
  - 표본 100명(쿼리 30명)은 경향 확인용이며 확정 성능 수치가 아니다.
  - E2는 사람이 아니라 LLM 자동 판정이다. spot-check로 신뢰도를 일부(불일치 30쌍 표본) 확인했지만 전체 556쌍을 사람이 본 것은 아니다.
  - M4 태깅(`gpt-5.4-nano`)과 E2 판정(`gpt-5.4-mini`)이 같은 회사·계열 모델이라, 완전히 독립적인 판정이라고 보기는 어렵다.
  - dev 30명으로 고른 tau·bonus가 실제 운영 규모(크리에이터 수백~수천 명)에서도 유효한지는 재검증이 필요하다.
  - 소개글 100명 중 86명은 LLM이 초안을 쓰고 14명만 직접 작성해, 문체가 실제 사용자 입력보다 균일할 수 있다.
  - 다음 실험 후보(비교군 확장): Qwen3-Embedding-0.6B, `bge-reranker-v2-m3`를 이번 M2/M3/M4와 같은 조건으로 비교하는 실험은 리뷰에서 제안됐으나 이번 재검증 범위 밖이라 별도 작업으로 남겨둔다.
