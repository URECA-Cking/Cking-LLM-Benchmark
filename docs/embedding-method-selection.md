# 임베딩 모델·추천 방식 선택 근거

## 결론

**임베딩 모델은 `bge-m3`, 유사도 방식은 M4(임베딩 + LLM 태그 보정) 또는 M3(임베딩 + zero-shot 태그 보정)를 1순위 후보로 제안한다. 다만 이것을 확정 채택으로 발표하지는 않는다.** E1(태깅 정확도)·E2(관련도)·E3(대표 사례) 세 지표 모두에서 `bge-m3`가 `text-embedding-3-small`을 일관되게 앞섰다. E3에서는 M2가 경품 잡음(X01)에 걸리는 반면 M3·M4는 통과해, 태그 보정이 실제로 잡음에 강하다는 근거가 됐다(아래 E3 절 참고). `M4_openai`는 재태깅 재현 실험에서 경품잡음(X02)에 새로 걸린 반면 `M4_bge-m3`는 두 번 다 통과했다 — LLM 태깅(M4)은 실행마다 결과가 달라질 수 있어 재현성 면에서는 zero-shot 태깅(M3)이 더 안정적이다. E2 신뢰구간도 M3·M4가 크게 겹쳐 통계적으로 못 가른다. 100명 규모 합성 데이터의 경향 확인이며, 실제 운영 규모 재검증 전까지는 결과를 확정 성능으로 보지 않는다.

> **2026-09-28 재검증**: 외부 코드 리뷰로 발견된 6개 문제(dev/test 라벨 누수, 판정시트 덮어쓰기, 캐시 과장, spot-check 편향, 경품잡음 미검증, Windows 해시 실패)를 모두 수정하고 파이프라인을 재실행했다([issue #4](https://github.com/URECA-Cking/Cking-LLM-Benchmark/issues/4)). 헤드라인 결론(`bge-m3` + M4/M3가 1순위)은 수정 전후로 바뀌지 않았다.
>
> **2026-09-28 재리뷰 라운드**: 이어진 재리뷰 3라운드([PR #5](https://github.com/URECA-Cking/Cking-LLM-Benchmark/pull/5))에서 spot-check 재현성, 판정 점수의 텍스트 해시 검증, 캐시 해시 범위(모델 정체성·프롬프트·temperature), 토큰 사용량 부분 캐시 히트 문제를 추가로 찾아 수정했다. 이 과정에서 LLM을 다시 태깅하게 됐고, 그 결과 `M4_openai`가 경품잡음(X02)에 새로 걸리는 걸 발견했다(아래 E3 참고). 아래 수치는 이 재리뷰까지 전부 반영한 최종 값이다.

## 측정 조건

- 데이터: `data/creators.csv` 100명(dev 30 / test 70), 쿼리 30명. `data/categories.csv` 10개
- 비교 대상: 임베딩 2종(`text-embedding-3-small`, `bge-m3`) × 방식 4~5종(M1~M4, 참고 R1·R2) = 11개 설정
- tau·bonus는 dev로만 그리드서치, 성적은 test로 계산 (`src/pipeline.py select-params`)
- 실행: 2026-09-28, `python3 -m src.pipeline embed / tag-llm / select-params / candidates / judge-sheet / auto-judge / score-judgments / report / spot-check / spot-check-report`

| M2_openai | 0.287 | [0.18, 0.39] | 0.337 | 0.773 |

판정은 사람이 아니라 **LLM 자동 판정**(`gpt-5.4-mini`, 559쌍, 비용 약 $0.14)으로 계산했다. M4 태깅에 쓴 모델(`gpt-5.4-nano`)보다 강한 모델을 판정에 써서, 같은 LLM이 자기 태깅을 스스로 좋게 채점하는 순환 편향을 줄였다.

**신뢰도 검증(spot-check)**: 처음 구현한 spot-check는 M4를 baseline들의 **합집합**과 비교해, "M4=A, M3=B, R2=A"처럼 다른 baseline이 우연히 같은 후보를 가지면 실제 차이를 놓치는 편향이 있었다(리뷰로 발견, 수정 후 회귀 테스트 추가). M4 vs M3, M4 vs R2를 각각 **양쪽 차집합**으로 직접 비교하도록 고치자 불일치 쌍이 12쌍에서 **139쌍**으로 늘었다 — 그만큼 처음 버전이 M4의 우위를 뒷받침하는 근거를 실제보다 좁게 보고 있었다는 뜻이다. 139쌍 전부를 사람이 보기엔 부담이 커서, 고정 시드로 무작위 **30쌍**을 뽑아 사람이 직접 재판정했다. 완전 일치율 0.77, ±1 이내 일치율 1.00으로 극단적 불일치(2점 차)는 없었다.

## E3. 대표 사례 (top-5, 11개 설정 전체, `src/pipeline.py report`)

| 설정 | 통과 | 실패 사례 |
| --- | ---: | --- |
| M1_openai | 3/7 | X12↔K03, X13↔S01, X14→K07, X15→F06 |
| M2_openai | 5/7 | X12↔K03, X14→K07 |
| M3_openai | 5/7 | X12↔K03, X14→K07 |
| M4_openai | 5/7 | X02 (경품잡음), X14→K07 |
| R2_openai | 5/7 | X14→K07, X15→F06 |
| R1 (분야만) | 5/7 | X14→K07, X15→F06 |
| M1_bge-m3 | 4/7 | X12↔K03, X14→K07, X15→F06 |
| M2_bge-m3 | 6/7 | X01 (경품잡음, 게임 크리에이터 G09 섞여 들어옴) |
| **M3_bge-m3** | **7/7** | 없음 |
| **M4_bge-m3** | **7/7** | 없음 |
| R2_bge-m3 | 5/7 | X14→K07, X15→F06 |

> LLM 태깅(M4)은 실행마다 결과가 조금씩 달라질 수 있다 — 캐시 해시 범위를 넓히는 재리뷰로 태깅을 한 번 더 돌리자 `M4_openai`가 새로 X02(경품잡음)에 걸렸다(최초 검증에서는 통과였음). `M4_bge-m3`는 두 번 다 7/7을 유지했다. zero-shot 태깅(M3)은 임베딩만으로 결정돼 두 번 다 안정적이었다.

"분야 넘기" 사례(X14, X15)는 입력 분야(declared) 기반 방식(R1, R2)에서만 계속 실패한다. declared 보정은 정의상 분야를 넘는 유사성을 찾지 못하므로 당연한 결과다. openai 임베딩은 X14→K07(요리 크리에이터의 유사 목록에 여행 크리에이터가 들어가야 하는 사례)에서 모든 방식이 약했고, bge-m3만 이를 풀었다.

**경품 잡음(X01·X02) 테스트는 리뷰 전까지 실제로는 검증되지 않고 있었다.** `Creator.input_text()`는 `bio`가 있으면 `events`를 아예 안 쓰는데, X01·X02는 경품 문구가 `events`에만 있고 `bio`는 따로 있어서 모델이 경품 문구를 한 번도 본 적이 없었다(리뷰로 발견). `bio`에 경품 문구를 직접 넣어 재검증하자 **M2_bge-m3(순수 임베딩)는 X01에서 "닌텐도 스위치" 문구에 끌려 무관한 게임 크리에이터(G09)를 상위 5명에 포함시켜 실패**했고, M3·M4(태그 보정 적용)는 여전히 통과했다. 태그 보정이 경품 잡음에 실제로 강하다는 것을 보여주는 첫 근거다.

## 선택 이유와 한계

- **bge-m3를 고른 이유**: E1·E2·E3 세 지표 모두에서 격차가 뚜렷했다. 특히 E1 Top-3 포함률 1.000과 E3 전체 통과는 우연이라 보기 어렵다.
- **M4·M3를 1순위로 하는 이유**: E3는 M3·M4가 동률(7/7, M2는 경품잡음 실패로 탈락)이라 이것만으로는 못 가른다. E2에서 M4가 M3보다 관련도가 약간 높지만(0.487 vs 0.447), 95% 신뢰구간이 겹친다([0.33, 0.64] vs [0.31, 0.59]). 게다가 재태깅 재현 실험에서 `M4_openai`가 경품잡음에 새로 걸린 것처럼, LLM 태깅은 실행마다 결과가 흔들릴 수 있다 — zero-shot 태깅(M3)은 그런 비결정성이 없다. M4를 쓰려면 **운영 중에도 LLM 태깅 파이프라인(비용·지연·장애 대응)을 유지해야 한다** — 이 운영 비용이나 재현성이 부담되면 M3(zero-shot 태그, 외부 LLM 불필요)가 더 신뢰할 수 있는 대안이다.
- **한계**:
  - 표본 100명(쿼리 30명)은 경향 확인용이며 확정 성능 수치가 아니다.
  - E2는 사람이 아니라 LLM 자동 판정이다. spot-check로 신뢰도를 일부(불일치 30쌍 표본) 확인했지만 전체 559쌍을 사람이 본 것은 아니다.
  - M4 태깅(`gpt-5.4-nano`)과 E2 판정(`gpt-5.4-mini`)이 같은 회사·계열 모델이라, 완전히 독립적인 판정이라고 보기는 어렵다.
  - dev 30명으로 고른 tau·bonus가 실제 운영 규모(크리에이터 수백~수천 명)에서도 유효한지는 재검증이 필요하다.
  - 소개글 100명 중 86명은 LLM이 초안을 쓰고 14명만 직접 작성해, 문체가 실제 사용자 입력보다 균일할 수 있다.
  - 다음 실험 후보(비교군 확장): Qwen3-Embedding-0.6B, `bge-reranker-v2-m3`를 이번 M2/M3/M4와 같은 조건으로 비교하는 실험은 리뷰에서 제안됐으나 이번 재검증 범위 밖이라 별도 작업(별도 브랜치/이슈)으로 남겨둔다.
