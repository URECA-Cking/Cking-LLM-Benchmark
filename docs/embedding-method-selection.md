# 임베딩 모델·추천 방식 선택 근거

## 결론

**임베딩 모델은 `bge-m3`, 유사도 방식은 M4(임베딩 + LLM 태그 보정)를 1순위 후보로 제안한다. 다만 이것을 확정 채택으로 발표하지는 않는다.** 4종 임베딩(`text-embedding-3-small`, `bge-m3`, `KURE-v1`, `Qwen3-Embedding-0.6B`) 중 E2 관련도는 `bge-m3` + M4(0.493)가 가장 높았지만, 한국어 특화 임베딩 `KURE-v1`이 강력한 대안으로 떠올랐다 — E1 태깅 정확도는 `bge-m3`보다도 높고(Top-1 0.914), **LLM 태그 보정 없이 순수 임베딩(M2)만으로 E3 7종 사례를 전부 통과**한 유일한 설정이다(`bge-m3`는 M2 단독으로는 경품잡음에서 실패, M3·M4를 얹어야 통과). 관련도는 `KURE-v1` + M4가 0.467로 `bge-m3` + M4와 신뢰구간이 겹쳐 통계적으로 구분되지 않는다. `Qwen3-Embedding-0.6B`는 E1·E3에서 `bge-m3`·`KURE-v1`보다 한 단계 약했다. `bge-m3` M2 후보를 `bge-reranker-v2-m3`로 재정렬하는 M5는 nDCG가 전체 설정 중 가장 높지만(0.561), 경품잡음(X01·X02) 둘 다에 걸려 태그 보정보다 잡음에 약하다 — 관련도를 높이는 것과 잡음에 강한 것은 서로 다른 문제임을 보여준다. 100명 규모 합성 데이터의 경향 확인이며, 실제 운영 규모 재검증 전까지는 결과를 확정 성능으로 보지 않는다.

> **2026-09-28 재검증**: 외부 코드 리뷰로 발견된 6개 문제(dev/test 라벨 누수, 판정시트 덮어쓰기, 캐시 과장, spot-check 편향, 경품잡음 미검증, Windows 해시 실패)를 모두 수정하고 파이프라인을 재실행했다([issue #4](https://github.com/URECA-Cking/Cking-LLM-Benchmark/issues/4)). 헤드라인 결론(`bge-m3` + M4가 1순위)은 수정 전후로 바뀌지 않았다.
>
> **2026-09-28 (2차) 비교군 확장**: 리뷰가 제안한 `Qwen3-Embedding-0.6B`에 더해, 한국어 소개글 데이터라는 점에서 `bge-m3`를 한국어로 파인튜닝한 `nlpai-lab/KURE-v1`도 같이 비교했다([issue #6](https://github.com/URECA-Cking/Cking-LLM-Benchmark/issues/6)). 아래 수치는 4종 임베딩을 전부 반영한 값이다.
>
> **2026-09-28 (3차) 리랭커 추가**: 리뷰가 제안한 다섯 번째 설정(`bge M2 + reranker`)을 M5로 구현해 추가했다. `bge-m3` M2 코사인 상위 20명을 `bge-reranker-v2-m3` cross-encoder로 다시 채점·정렬한다(이슈 #6). 별도 리뷰 코멘트로 발견된 캐시 무결성(P1)·spot-check 재현성(P2) 문제도 같이 수정했다([PR #5](https://github.com/URECA-Cking/Cking-LLM-Benchmark/pull/5)).

## 측정 조건

- 데이터: `data/creators.csv` 100명(dev 30 / test 70), 쿼리 30명. `data/categories.csv` 10개
- 비교 대상: 임베딩 4종(`text-embedding-3-small`, `bge-m3`, `KURE-v1`, `Qwen3-Embedding-0.6B`) × 방식 4~5종(M1~M4, 참고 R1·R2) + M5(bge-m3 M2 + `bge-reranker-v2-m3` 재정렬, 1회) = 22개 설정
- tau·bonus는 dev로만 그리드서치, 성적은 test로 계산 (`src/pipeline.py select-params`)
- 실행: 2026-09-28, `python3 -m src.pipeline embed / tag-llm / select-params / candidates / judge-sheet / auto-judge / score-judgments / report / spot-check / spot-check-report`

M4 vs M3, M4 vs R2를 각각 **양쪽 차집합**으로 직접 비교하도록 고치자 불일치 쌍이 12쌍에서 **141쌍**으로 늘었다 — 그만큼 처음 버전이 M4의 우위를 뒷받침하는 근거를 실제보다 좁게 보고 있었다는 뜻이다. 141쌍 전부를 사람이 보기엔 부담이 커서, 고정 시드로 무작위 **30쌍**을 뽑아 사람이 직접 재판정했다. 완전 일치율 0.80, ±1 이내 일치율 1.00으로 극단적 불일치(2점 차)는 없었다.

"분야 넘기" 사례(X14, X15)는 입력 분야(declared) 기반 방식(R1, R2)에서만 계속 실패한다. declared 보정은 정의상 분야를 넘는 유사성을 찾지 못하므로 당연한 결과다. openai 임베딩은 X14→K07(요리 크리에이터의 유사 목록에 여행 크리에이터가 들어가야 하는 사례)에서 모든 방식이 약했고, bge-m3·KURE-v1(M2 이상)만 이를 풀었다.

**경품 잡음(X01·X02) 테스트는 리뷰 전까지 실제로는 검증되지 않고 있었다.** `Creator.input_text()`는 `bio`가 있으면 `events`를 아예 안 쓰는데, X01·X02는 경품 문구가 `events`에만 있고 `bio`는 따로 있어서 모델이 경품 문구를 한 번도 본 적이 없었다(리뷰로 발견). `bio`에 경품 문구를 직접 넣어 재검증하자 **M2_bge-m3(순수 임베딩)는 X01에서 "닌텐도 스위치" 문구에 끌려 무관한 게임 크리에이터(G09)를 상위 5명에 포함시켜 실패**했고, M3·M4(태그 보정 적용)는 여전히 통과했다. 태그 보정이 경품 잡음에 실제로 강하다는 것을 보여주는 첫 근거다.

**KURE-v1은 M2(순수 임베딩, 태그 보정 없음)만으로도 이 7종 사례를 전부 통과한 유일한 설정이다.** bge-m3는 M2 단독으로는 X01 경품잡음에 걸리고 M3·M4로 태그 보정을 얹어야 통과하는 반면, KURE-v1은 태그 보정 없이도 경품 문구에 끌리지 않았다. LLM 태깅(M4)이나 zero-shot 태깅(M3) 없이도 같은 견고함을 얻을 수 있다는 뜻으로, 운영 비용·지연 관점에서 눈여겨볼 결과다 — 다만 E2 관련도는 M2_kure-v1(0.420)이 M4_bge-m3(0.493)보다 낮아, "더 견고하지만 관련도는 살짝 아쉬운" 트레이드오프다.

**M5(bge-m3 M2 + 재정렬)는 관련도·nDCG를 크게 올리지만(M2 대비 관련도 0.393→0.473, nDCG는 전체 설정 중 최고인 0.561) 경품잡음(X01·X02)에는 M2보다도 더 취약해졌다** — M2는 X01만 실패했지만 M5는 X01·X02 둘 다 게임 크리에이터(G05)를 상위 5명에 포함시켰다. 태그 보정(M3·M4)은 "태그가 겹치는가"라는 구조화된 신호를 더해 경품 문구 같은 표면적 겹침을 걸러내는 반면, cross-encoder 리랭커는 두 텍스트를 통째로 비교하기 때문에 오히려 경품 문구 자체의 표면적 유사성에 더 크게 반응한 것으로 보인다. **관련도를 높이는 것과 잡음에 강한 것은 서로 다른 문제**라는 근거다.

## 선택 이유와 한계

- **bge-m3 + M4를 1순위로 하는 이유**: E2 관련도 점 추정치가 4개 임베딩 중 가장 높았다(0.493). 다만 KURE-v1 + M4(0.467)·Qwen3 + M4(0.487)와 신뢰구간이 크게 겹쳐, 이 규모(쿼리 30명)에서는 "확실히 1등"이라기보다 "동급 상위권 중 점 추정치가 가장 높다" 정도로 해석해야 한다.
- **KURE-v1을 유력한 대안으로 남기는 이유**: E1 Top-1 정확도가 네 모델 중 가장 높고(0.914), **M2(순수 임베딩, 태그 보정 없음)만으로 E3 7종 사례를 전부 통과한 유일한 설정**이다. bge-m3는 M2 단독으로 경품잡음(X01)에 걸려 M3·M4의 태그 보정이 필요했던 반면, KURE-v1은 태그 보정 없이도 견고했다. LLM 태깅·zero-shot 태깅 없이 순수 임베딩만으로 운영할 수 있다면 파이프라인이 단순해지고 M4의 LLM 의존(비용·지연·장애 대응)도 없앨 수 있다 — 대신 관련도는 M2_kure-v1(0.420)이 M4_bge-m3(0.493)보다 낮아, 트레이드오프로 봐야 한다.
- **Qwen3-Embedding-0.6B는 이번 데이터에서 한 단계 아래**: E1 Top-1 0.886, E3에서 M1~M3가 F01↔F02(동의어) 사례를 놓쳐 bge-m3·KURE-v1보다 약했다. E2 관련도(M4 기준 0.487)만 보면 비슷하지만, E1·E3를 같이 보면 우선순위는 낮다.
- **M3를 M4의 대안으로 남기는 이유**: bge-m3·KURE-v1 둘 다 M3·M4가 E3에서 동률(7/7)이고 E2 차이도 신뢰구간이 겹친다. M4를 쓰려면 **운영 중에도 LLM 태깅 파이프라인(비용·지연·장애 대응)을 유지해야 한다** — 이 운영 비용이 부담되면 M3(zero-shot 태그, 외부 LLM 불필요)로도 충분히 근거 있는 대안이다.
- **M5(리랭커)는 채택하지 않는 이유**: nDCG는 전체 설정 중 가장 높지만(0.561), 경품잡음 검증(X01·X02)에서 M2보다도 더 많이 실패했다(2/2 실패, M2는 1/2). 관련도만 보면 매력적이지만 잡음 내성이 약해, 이 벤치마크의 "경품·잡음 문구에 흔들리지 않아야 한다"는 요구를 채우지 못한다. 다만 관련도 자체는 태그 보정 없이도 M4에 근접한 수준까지 올라간다는 점에서, 잡음 필터링을 별도로 앞단에 두는 조건이라면 재검토할 만하다.
- **한계**:
  - 표본 100명(쿼리 30명)은 경향 확인용이며 확정 성능 수치가 아니다.
  - E2는 사람이 아니라 LLM 자동 판정이다. spot-check로 신뢰도를 일부(bge-m3 기준 불일치 30쌍 표본) 확인했지만 전체 681쌍을 사람이 본 것은 아니고, KURE-v1·Qwen3·M5 쪽 불일치는 별도로 spot-check하지 않았다.
  - M4 태깅(`gpt-5.4-nano`)과 E2 판정(`gpt-5.4-mini`)이 같은 회사·계열 모델이라, 완전히 독립적인 판정이라고 보기는 어렵다.
  - dev 30명으로 고른 tau·bonus가 실제 운영 규모(크리에이터 수백~수천 명)에서도 유효한지는 재검증이 필요하다.
  - 소개글 100명 중 86명은 LLM이 초안을 쓰고 14명만 직접 작성해, 문체가 실제 사용자 입력보다 균일할 수 있다.
  - M5는 M2가 이미 추린 상위 20명만 재정렬한다 — 리랭커가 M2의 오답(경품잡음으로 끌려온 후보 포함)을 상위권으로 더 끌어올릴 수는 있어도, M2가 애초에 놓친 후보를 새로 찾아오지는 못한다.
