# 임베딩 모델·추천 방식 선택 근거

## 결론

**임베딩 모델은 `bge-m3`, 유사도 방식은 M4(임베딩 + LLM 태그 보정) 또는 M3(임베딩 + zero-shot 태그 보정)를 1순위 후보로 제안한다. 다만 이것을 확정 채택으로 발표하지는 않는다.** 4종 임베딩(`text-embedding-3-small`, `bge-m3`, `KURE-v1`, `Qwen3-Embedding-0.6B`) 중 E2 관련도 점 추정치는 `bge-m3`+M4와 `Qwen3`+M4가 0.487로 공동 1위였고, 한국어 특화 임베딩 `KURE-v1`도 강력한 대안이다 — E1 태깅 정확도가 네 임베딩 중 가장 높고(Top-1 0.914), **LLM 태그 보정 없이 순수 임베딩(M2)만으로 E3 7종 사례를 전부 통과**한 유일한 설정이다(`bge-m3`는 M2 단독으로는 경품잡음에서 실패, M3·M4를 얹어야 통과). `Qwen3-Embedding-0.6B`는 관련도는 높지만(쿼리 프롬프트 적용 재측정 후 M4 기준 0.473) E1·E3에서 `bge-m3`·`KURE-v1`보다 한 단계 약했다 — 공식 권장 쿼리 프롬프트를 적용해 재측정하자 E3에서 M4_qwen3가 5/7→6/7로 올랐지만(아래 한계 참고), 여전히 X14→K07 "분야 넘기" 사례는 못 풀어 최상위권과는 차이가 있다. `bge-m3` M2 후보를 `bge-reranker-v2-m3`로 재정렬하는 M5는 nDCG가 전체 설정 중 가장 높지만(0.558), 경품잡음(X01·X02) 둘 다에 걸려 태그 보정보다 잡음에 약하다 — 관련도를 높이는 것과 잡음에 강한 것은 서로 다른 문제임을 보여준다.

**LLM 재태깅 재현 실험에서 드러난 것**: 캐시 무효화를 재리뷰로 고치면서 LLM 태깅을 두 번 다시 돌렸는데, 두 번째 실행에서는 `M4_openai`·`M4_qwen3`가 X02 경품잡음에 새로 걸렸다(`M4_bge-m3`만 두 번 다 통과). LLM 태그(M4)는 모델 응답이 실행마다 조금씩 달라질 수 있어 E3 통과 여부가 흔들리는 반면, zero-shot 태그(M3)는 임베딩만으로 결정돼 `bge-m3`·`KURE-v1`에서 두 번 다 7/7로 안정적이었다. 관련도만 보면 M4가 근소 우위지만, **재현성을 중요하게 본다면 M3가 더 신뢰할 수 있는 선택**이다. 100명 규모 합성 데이터의 경향 확인이며, 실제 운영 규모 재검증 전까지는 결과를 확정 성능으로 보지 않는다.

**Qwen3 쿼리 프롬프트 재측정**: Qwen3-Embedding 모델에 등록된 쿼리용 instruct 프롬프트(`prompt_name="query"`)를 평가 쿼리 30명에 적용해 재측정했다(이슈 #8, `src/clients/local_embedding.py`·`_query_prompted_vectors()`). **신뢰도 검증(spot-check)**: 처음 구현한 spot-check는 M4를 baseline들의 **합집합**과 비교해, "M4=A, M3=B, R2=A"처럼 다른 baseline이 우연히 같은 후보를 가지면 실제 차이를 놓치는 편향이 있었다(리뷰로 발견, 수정 후 회귀 테스트 추가). M4 vs M3, M4 vs R2를 각각 **양쪽 차집합**으로 직접 비교하도록 고치자 불일치 쌍이 12쌍에서 **139쌍**으로 늘었다 — 그만큼 처음 버전이 M4의 우위를 뒷받침하는 근거를 실제보다 좁게 보고 있었다는 뜻이다. 139쌍 전부를 사람이 보기엔 부담이 커서, 고정 시드로 무작위 **30쌍**을 뽑아 사람이 직접 재판정했다. 완전 일치율 0.77, ±1 이내 일치율 1.00으로 극단적 불일치(2점 차)는 없었다.

> LLM 태깅(M4)은 실행마다 결과가 조금씩 달라질 수 있다 — 캐시 무효화 재리뷰로 태깅을 한 번 더 돌리자 `M4_openai`·`M4_qwen3`·`M4_kure-v1`가 새로 X02에 걸렸고, `M4_bge-m3`만 두 번 다 7/7을 유지했다. zero-shot 태깅(M3)은 임베딩만으로 결정돼 `bge-m3`·`KURE-v1`에서 두 번 다 안정적으로 7/7이었다. **이후 Qwen3에 쿼리 프롬프트를 적용해 재측정하자 `M4_qwen3`가 X02를 다시 통과해 6/7로 올랐다** — 위 표는 이 재측정 값이다.

"분야 넘기" 사례(X14, X15)는 입력 분야(declared) 기반 방식(R1, R2)에서만 계속 실패한다. declared 보정은 정의상 분야를 넘는 유사성을 찾지 못하므로 당연한 결과다. openai 임베딩은 X14→K07(요리 크리에이터의 유사 목록에 여행 크리에이터가 들어가야 하는 사례)에서 모든 방식이 약했고, bge-m3·KURE-v1(M2 이상)만 이를 풀었다.

**경품 잡음(X01·X02) 테스트는 리뷰 전까지 실제로는 검증되지 않고 있었다.** `Creator.input_text()`는 `bio`가 있으면 `events`를 아예 안 쓰는데, X01·X02는 경품 문구가 `events`에만 있고 `bio`는 따로 있어서 모델이 경품 문구를 한 번도 본 적이 없었다(리뷰로 발견). `bio`에 경품 문구를 직접 넣어 재검증하자 **M2_bge-m3(순수 임베딩)는 X01에서 "닌텐도 스위치" 문구에 끌려 무관한 게임 크리에이터(G09)를 상위 5명에 포함시켜 실패**했고, M3·M4(태그 보정 적용)는 여전히 통과했다. 태그 보정이 경품 잡음에 실제로 강하다는 것을 보여주는 첫 근거다.

**KURE-v1은 M2(순수 임베딩, 태그 보정 없음)만으로도 이 7종 사례를 전부 통과한 유일한 설정이다.** bge-m3는 M2 단독으로는 X01 경품잡음에 걸리고 M3·M4로 태그 보정을 얹어야 통과하는 반면, KURE-v1은 태그 보정 없이도 경품 문구에 끌리지 않았다. LLM 태깅(M4)이나 zero-shot 태깅(M3) 없이도 같은 견고함을 얻을 수 있다는 뜻으로, 운영 비용·지연 관점에서 눈여겨볼 결과다 — 다만 E2 관련도는 M2_kure-v1(0.420)이 M4_bge-m3(0.487)보다 낮아, "더 견고하지만 관련도는 살짝 아쉬운" 트레이드오프다.

**M5(bge-m3 M2 + 재정렬)는 관련도·nDCG를 크게 올리지만(M2 대비 관련도 0.393→0.473, nDCG는 전체 설정 중 최고인 0.558) 경품잡음(X01·X02)에는 M2보다도 더 취약해졌다** — M2는 X01만 실패했지만 M5는 X01·X02 둘 다 게임 크리에이터(G05)를 상위 5명에 포함시켰다. 태그 보정(M3·M4)은 "태그가 겹치는가"라는 구조화된 신호를 더해 경품 문구 같은 표면적 겹침을 걸러내는 반면, cross-encoder 리랭커는 두 텍스트를 통째로 비교하기 때문에 오히려 경품 문구 자체의 표면적 유사성에 더 크게 반응한 것으로 보인다. **관련도를 높이는 것과 잡음에 강한 것은 서로 다른 문제**라는 근거다.

## 선택 이유와 한계

- **bge-m3 + M4를 1순위 중 하나로 하는 이유**: E2 관련도 점 추정치가 Qwen3+M4와 공동 1위(0.487)였고, KURE-v1+M4(0.467)·M5_bge-m3(0.473)도 근접해 신뢰구간이 크게 겹친다. 재태깅 재현 실험에서 `M4_bge-m3`만 두 번 다 경품잡음 E3를 통과해, 상위권 중에서는 가장 안정적이었다.
- **KURE-v1을 유력한 대안으로 남기는 이유**: E1 Top-1 정확도가 네 모델 중 가장 높고(0.914), **M2(순수 임베딩, 태그 보정 없음)만으로 E3 7종 사례를 전부 통과한 유일한 설정**이다. bge-m3는 M2 단독으로 경품잡음(X01)에 걸려 M3·M4의 태그 보정이 필요했던 반면, KURE-v1은 태그 보정 없이도 견고했다. LLM 태깅·zero-shot 태깅 없이 순수 임베딩만으로 운영할 수 있다면 파이프라인이 단순해지고 M4의 LLM 의존(비용·지연·장애 대응)도 없앨 수 있다 — 대신 관련도는 M2_kure-v1(0.420)이 M4_bge-m3(0.487)보다 낮아, 트레이드오프로 봐야 한다.
- **bge-m3 vs KURE-v1 타겟 spot-check(이슈 #8)**: 두 모델이 실제로 다르게 추천한 30쌍(M3_bge-m3 vs M2_kure-v1 대칭차집합에서 표본 추출)을 사람이 직접 재판정했다. 자동 판정과의 일치율은 높았다(완전 일치 0.90, ±1 이내 1.00, 2점 차 불일치 없음) — 이 30쌍에서의 E2 점수를 신뢰할 근거가 된다. 그리고 **의견이 갈린 pick만 따로 보면 bge-m3 쪽이 더 관련도가 높았다**: `M3_bge-m3`만 고른 15개 픽의 평균 관련도는 0.33, `M2_kure-v1`만 고른 15개 픽은 0.13이었다. 표본이 작아(각 15개) 확정적이진 않지만, 전체 E2 집계(M2_kure-v1 0.420 vs M3_bge-m3 0.447)와 같은 방향이라 bge-m3 우위를 보강하는 근거다.
- **Qwen3-Embedding-0.6B는 이번 데이터에서 한 단계 아래 — 쿼리 프롬프트를 적용해 재측정한 뒤에도 마찬가지다**: E1 Top-1 0.886, E3에서 M1~M3가 F01↔F02(동의어) 사례를 놓쳐 bge-m3·KURE-v1보다 약했다. `LocalEmbeddingClient`가 원래 bge-m3·KURE-v1과 동일하게 접두어 없이 인코딩했는데, Qwen3-Embedding은 모델 자체에 쿼리용 instruct 프롬프트가 등록돼 있고 공식 사용법은 검색 질의 쪽에 이를 적용하길 권장한다는 지적(리뷰로 발견)에 따라 **평가 쿼리 30명에 이 프롬프트를 적용해 재측정했다**(`_query_prompted_vectors()`, 이슈 #8). 결과: E2 관련도는 방향이 엇갈리며 신뢰구간 안에서 변화(M4 기준 0.487→0.473), **E3는 M4_qwen3가 5/7→6/7로 개선**(경품잡음 X02를 더는 놓치지 않음) — 그래도 X14→K07 "분야 넘기"는 여전히 못 풀어 bge-m3·KURE-v1과 동률에는 못 미친다. 이 프롬프트 문구 자체가 "웹 검색 질의에 답하는 문서를 찾으라"는 검색 과제용이라 크리에이터 간 유사도라는 이 벤치마크의 실제 과제와 의미가 정확히 맞지는 않으므로, **실제 서비스에 쓸 쿼리 형식(예: 사용자 취향 요약문)이 정해지면 그 조건으로 다시 확인해야 한다** — 지금 값은 "공식 권장 프롬프트를 그대로 적용"한 조건일 뿐 최종 서비스 조건이 아니다.
- **M3를 M4의 대안으로 남기는 이유**: bge-m3·KURE-v1 둘 다 M3·M4가 E3에서 동률(7/7)이고 E2 차이도 신뢰구간이 겹친다. M4를 쓰려면 **운영 중에도 LLM 태깅 파이프라인(비용·지연·장애 대응)을 유지해야 한다** — 이 운영 비용이 부담되면 M3(zero-shot 태그, 외부 LLM 불필요)로도 충분히 근거 있는 대안이다.
- **M5(리랭커)는 채택하지 않는 이유**: nDCG는 전체 설정 중 가장 높지만(0.558), 경품잡음 검증(X01·X02)에서 M2보다도 더 많이 실패했다(2/2 실패, M2는 1/2). 관련도만 보면 매력적이지만 잡음 내성이 약해, 이 벤치마크의 "경품·잡음 문구에 흔들리지 않아야 한다"는 요구를 채우지 못한다. 다만 관련도 자체는 태그 보정 없이도 M4에 근접한 수준까지 올라간다는 점에서, 잡음 필터링을 별도로 앞단에 두는 조건이라면 재검토할 만하다.
- **한계**:
  - 표본 100명(쿼리 30명)은 경향 확인용이며 확정 성능 수치가 아니다.
  - E2는 사람이 아니라 LLM 자동 판정이다. spot-check로 신뢰도를 일부 확인했다 — bge-m3 내부 비교(M4 vs M3/R2, 30쌍) 그리고 bge-m3 vs KURE-v1 비교(30쌍) 둘 다 자동 판정과 높은 일치율(각각 0.77·0.90)을 보였지만, 전체 676쌍을 사람이 본 것은 아니고 Qwen3·M5 쪽 불일치는 아직 별도로 spot-check하지 않았다.
  - M4 태깅(`gpt-5.4-nano`)과 E2 판정(`gpt-5.4-mini`)이 같은 회사·계열 모델이라, 완전히 독립적인 판정이라고 보기는 어렵다.
  - dev 30명으로 고른 tau·bonus의 민감도는 합성 300명으로 확인했다(아래 "dev 규모 민감도" 절). 다만 합성 데이터가 한 LLM이 쓴 균일한 문체라 실제 운영 규모(수백~수천 명)의 다양성까지 검증한 것은 아니다.
  - 소개글 100명 중 86명은 LLM이 초안을 쓰고 14명만 직접 작성해, 문체가 실제 사용자 입력보다 균일할 수 있다.
  - M5는 M2가 이미 추린 상위 20명만 재정렬한다 — 리랭커가 M2의 오답(경품잡음으로 끌려온 후보 포함)을 상위권으로 더 끌어올릴 수는 있어도, M2가 애초에 놓친 후보를 새로 찾아오지는 못한다.
  - **이 벤치마크는 "크리에이터 소개글 → 유사 크리에이터" 과제만 검증한다.** 실제 AI 취향 분석 기능은 사용자의 취향을 요약한 텍스트를 쿼리로 크리에이터를 추천할 가능성이 높은데(리뷰로 지적), 그 쿼리가 어떤 형태일지(요약 방식, 길이, 톤)는 아직 정해지지 않았고 이 벤치마크의 합성 데이터에도 그런 사용자 취향 쿼리 샘플이 없다. 여기서 나온 순위가 크리에이터 소개글끼리의 유사도에서는 유효해도, 실제 사용자 취향 쿼리 → 크리에이터 과제에 그대로 옮겨진다는 보장은 없다 — 쿼리 형식이 정해지면 별도 E2E 검증이 필요하다.

## dev 규모 민감도 (이슈 #8, `src/pipeline.py dev-sensitivity`)

dev 30명으로 tau·bonus를 고른 것이 표본 운에 얼마나 좌우되는지 확인했다. 기존 dev 30명 + 합성 300명(`data/creators_large.csv`, gpt-5.4-mini 생성, 카테고리당 30명, 복수 분야·입력분야 오기재·이벤트만 있는 사례 각 30명)을 후보 풀로 두고, 크기 30/60/120/240 부분표본을 각 20번 뽑아 `select-params`와 같은 절차로 고른 뒤 기존 100명에서 gold 기준 대리 지표(태그 F1, 쿼리 30명 P@5)로 평가했다. 기존 dev 30명 그대로 고른 값이 `selected_params.json`과 4개 모델 모두 일치함을 확인했다.

| 모델 | tau 표준편차 (30 → 240) | 태그 F1 평균 (30 → 240) |
| --- | --- | --- |
| text-embedding-3-small | 0.022 → 0.006 | 0.533 → 0.546 |
| bge-m3 | 0.009 → 0.001 | 0.718 → 0.718 |
| kure-v1 | 0.015 → 0.005 | 0.722 → 0.736 |
| qwen3-embedding-0.6b | 0.022 → 0.003 | 0.711 → 0.729 |

- **tau는 dev 30명에서도 이미 안정적이다.** 평균은 크기와 거의 무관(bge-m3 0.497 → 0.496)하고 표준편차만 줄어든다.
- **bonus는 값 자체는 자주 바뀐다.** 최빈값 비율이 대부분 50~70%이고 0.2·0.3·0.4 같은 이웃 격자값 사이를 오간다. 그러나 **test P@5는 거의 그대로**다(M3: bge-m3 0.708~0.720, Qwen3 0.619~0.638. M4는 모델별로 크기와 무관하게 사실상 동일) — 격자 안의 이웃 값들은 성능 차이가 작아 어느 값을 골라도 결과가 비슷하다.
- **예외: R2(입력분야 태그)는 dev가 커질수록 bonus가 0.1로 내려가고 P@5가 조금 낮아진다**(bge-m3 0.958 → 0.920, KURE-v1 0.960 → 0.900). 합성 데이터에 입력분야 오기재 사례가 10%로 기존 dev보다 많아, 크기가 아니라 **데이터 분포**가 바뀐 효과로 보는 게 맞다. R2는 참고 기준선일 뿐 채택 후보가 아니므로 결론에는 영향이 없다.
- 결론: 방식 순위를 뒤집을 만큼의 흔들림은 없었다. 다만 합성 데이터가 단일 LLM 생성이라 균일하고, 240명 부분표본은 330명 풀과 겹쳐 분산을 실제보다 작게 본다. test 지표도 LLM 판정 E2가 아닌 gold 기반 대리 지표다.
