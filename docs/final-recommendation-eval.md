# 최종 추천 방식 선정 실험 설계

> 상태: 최종 입력 100개·801쌍 사람 평가와 집계 완료. 일반 소개는 M4, 짧은 소개는 M2를 잠정 선택한다. 서비스 적용 검증은 별도다.

**이번 결정 범위:** 소개글 기반 추천 엔진의 프로젝트 적용 후보를 선택한다. 독립 다인 검증과 실제 개인화 성능은 별도 검증으로 남긴다.

**결론부터 보기:** 일반 소개는 M4(P@5 0.827)를 잠정 선택한다. H4의 추가 개선은 +0.008로 작고 불확실해 세부 태그를 기본 채택하지 않는다.
짧은 소개는 차이가 불명확하므로 단순한 M2를 잠정 선택한다.
[최종 성적표·비교 구간·선택 이유](#14-최종-사람-평가-결과와-선택) · [집계 재현·검증](#15-집계-재현과-실행-검증)

## 1. 이번에 결정할 것

**소개글 기반 후보 검색에 M2·M3·M4·H3·H4 중 무엇을 사용할지 결정한다.**
현재는 소개글 데이터만 확보돼 있다. 실제 선택 태그·즐겨찾기 경로의 서비스 품질은 이번에 확정하지 않는다. 합성 입력을 추가하더라도 보조 탐색으로 분리한다.
인기순 건너뛰기는 개인화 품질 비교와 분리한다. 최종 결과로 서비스 클릭·즐겨찾기 전환 효과까지 입증했다고 표현하지 않는다.

| 결정 | 근거 |
| --- | --- |
| 임베딩만으로 충분한가 | M3−M2의 사람 품질 차이와 운영 복잡성 |
| LLM 태깅이 필요한가 | M4−M3의 사람 품질 차이와 분류 비용 |
| 세부 주제 보정이 필요한가 | H3−M3, H4−M4의 추가 가치 |
| 세부 LLM 보정이 비용을 정당화하는가 | H4−H3의 품질·분류 비용 |
| 정보 부족 입력을 어떻게 처리할까 | 내용 충분/부족 그룹의 품질·판단 가능률·반환율 |

## 2. 지금까지 확인한 것

- 기존 v4 표본은 반복 관찰한 탐색 데이터다. 최종 평가 표본으로 재사용하지 않는다.
- 상위 M4 가산점 1.5배는 기존과 468개 입력 모두 같은 순위였다.
- 일반 소개의 H4 총량 유지 조건은 0.641→0.655, 가산점 증가 조건은 0.664였다. 모두 LLM 판정 결과다.
- 즐겨찾기는 H4 총량 유지 조건에서 개선되지 않았고 주 조건의 개선 구간도 0을 포함했다.
- 사용자 1명의 태그 20개·추천 20쌍은 진단이다. 방식별 최종 성능·일치율 게이트가 아니다.
- 정보 없는 소개글·연락처·광고 문구가 유사한 부적절 사례를 확인했다. 정보 부족 처리의 개선 효과는 아직 검증하지 않았다.

## 3. 비교 방법과 공통 조건

| 후보 | 검색·보정 | 개발 단계에서 정할 값 |
| --- | --- | --- |
| M2 | 소개글 임베딩 코사인 | 공통 입력 정리·검색 가능 조건 |
| M3 | M2 + zero-shot 상위 태그 보정 | 상위 태그 임계값·가산점 |
| M4 | M2 + LLM 상위 태그 보정 | 분류 프롬프트·가산점 |
| H3 | M3 + 세부 임베딩 태그 보정 | 세부 임계값·상위/세부 가중치 |
| H4 | M4 + LLM 세부 태그 보정 | 분류 프롬프트·상위/세부 가중치 |

- 이번 비교는 bge-m3 기반 추천 방식 선택이다. 임베딩 모델 종류를 다시 선택하는 실험은 아니다.
- 같은 후보 풀·소개글·직접 입력 태그·제외 규칙·상위 5명·동점 ID 정렬을 쓴다.
- 직접 선택한 크리에이터 태그가 확보되면 그것만 사용하는 공통 기준선을 추가한다. 자동 분류와 직접 선택 태그를 혼합해 같은 것으로 부르지 않는다.
- 즐겨찾기 기본 집계는 seed별 조정 점수의 최댓값이다. 바꾸려면 개발 단계에서 비교한 뒤 최종 평가 전에 고정한다.
- 모델 호출은 오프라인 생성 단계에 한정한다. 추천 조회 중 LLM 호출을 추가하지 않는다.
- 현재 로컬 임베딩으로 평가하면 그 범위로 결론을 제한한다. 서비스 API 임베딩으로 배포할 경우 개발 단계에서 벡터·분류·순위 정합성을 별도로 확인하고 최종 모델/제공자를 고정한다.

### 정보 부족 처리: 모든 방법에 같은 규칙 적용

단순 글자 수만으로 판단하지 않는다. 연락처·링크·구독 요청·홍보 문구를 제외한 뒤 주제·활동 정보가 남는지 확인한다.
개발 표본에서 사람이 정보 충분/부족/애매를 판정해 처리 규칙을 확정한다. 최종 표본의 그룹 표기는 추천 결과를 보기 전에 수행한다.

| 입력 상태 | 제안 동작 | 평가 구분 |
| --- | --- | --- |
| 내용 충분 | 선택한 방식으로 의미 검색 | 의미 추천 품질 |
| 내용 부족·직접 선택 태그 있음 | 직접 태그 기준 후보 제공 | 태그 대체 추천 품질 |
| 내용 부족·태그도 없음 | 유사 추천은 반환하지 않음, 일반 추천에서는 별도 기본 목록 허용 | 반환율·판단 가능률·기본 추천 분리 |

이벤트·영상 제목 등 정보를 추가한다면 모든 방법에 같은 입력을 제공하고 입력 버전을 새로 고정한다.
인기 후보를 유사 추천으로 섞어 적합성 향상이라고 보고하지 않는다. 대체 경로의 실제 효과는 별도 평가한다.

## 4. 데이터와 분할

| 데이터 | 용도 | 제한 |
| --- | --- | --- |
| 지금까지의 v4·사람 진단 | 오류 분석·분류 기준 보완 | 최종 성적표로 재사용 금지 |
| 개발 표본 | 임계값·가중치·정보 부족 규칙·판정 안내 확정 | 결과를 보고 조정 가능 |
| 새 최종 표본 | 방식 비교·채택 판단 | 설정 변경·추가 튜닝 금지 |

새 데이터의 의미는 새 ID만이 아니라 아직 품질 결과를 관찰하지 않은 평가 입력이다. 가능하면 신규 채널/갱신 소개글을 확보한다.
개발/최종 seed는 크리에이터 기준으로 분리한다. 사용자가 여러 입력을 제공하면 같은 사용자의 입력은 한 분할에만 둔다.
실제 이력은 수집 기준 시점을 고정하고 미래 행동을 입력하지 않는다. 후보 풀은 최종 실행 전 별도로 고정한다.
후보 검색은 고정 풀을 사용하는 오프라인 상황이다. 평가 seed·직접 태그·채점 정답을 후보 태깅 최적화에 사용하지 않는다.

### 확정 표본 규모

| 경로 | 제안 수 | 구성 |
| --- | ---: | --- |
| 크리에이터 선택 | 100 | 일반75·짧은 소개25; 짧음은 기존 길이 기준이며 의미적 정보 부족과 다름 |
| 직접 태그 선택 | 이번 실행 제외 | 실제 입력 확보 후 별도 검증 |
| 실제 즐겨찾기 | 이번 실행 제외 | 실제 이력 확보 후 별도 검증 |

사용자 승인으로 미평가 입력 100개를 확정했다. 다섯 방식의 상위 5명 합집합은 중복 제거 후 801쌍이다.
이 표본 수가 최소 차이 0.03을 충분히 검출한다고 보장하지 않는다. 불확실한 결과는 단순한 방식을 잠정 선택하는 근거로 사용한다.
같은 명령으로 나눠 채점하고 재개할 수 있다. 결과를 보고 표본 수나 설정을 바꾸지 않는다.

## 5. 개발 단계: 최종 조건 선택

1. 태그 정의와 주된 활동 기준을 보완하고 의미적 분류 오류를 점검한다.
2. 개발용 입력에서 M3/M4/H3/H4의 임계값·가산점을 비교한다. 기존 수치는 출발값으로만 사용한다.
3. H4는 총량 유지와 증가를 모두 개발 조건으로 비교한다. 상위만 일치하는 후보의 보정 축소와 세부 일치 가산을 구분해 기록한다.
4. 정보 부족 규칙과 직접 태그/기본 추천 대체를 점검한다.
5. 개발용 품질과 비용으로 방법당 설정 하나를 선택한다. 최종 평가에 여러 H4 설정을 넣고 좋은 결과를 사후 선택하지 않는다.
6. 최종 표본 수·품질 허용값·비용 상한·통계 비교 목록·평가자와 역할을 확정한다.

## 6. 사람 평가

**확정: 사용자 1명이 채점한다.** 구현·탐색에 참여한 평가자이므로 개인 선호·설계자 편향의 한계를 명시한다. 방법을 숨겨도 이 한계가 없어지지는 않는다.
개발 표본으로 안내를 정한 뒤 최종 채점에서는 방법명·모델 태그·점수·순위·LLM 답을 숨긴다.
추천 입력과 후보의 소개글, 확보된 실제 입력만 동일하게 보여준다. 방법별 후보 합집합의 동일 쌍은 평가자별 한 번 채점한다.
표본 ID·순서 seed·내용 hash를 저장하고 사람이 채점한 점수는 LLM 점수와 별도 파일로 보관한다.

| 답 | 판정 기준 |
| --- | --- |
| 1 적절 | 입력의 실제 주제·활동과 연결돼 추천할 근거가 있음 |
| 0 부적절 | 주제가 다르거나, 인사·연락처·형식 같은 표현만 비슷함 |
| U 판단 어려움 | 제공한 정보만으로 관련 여부 판단 불가 |

태그 입력은 선택 관심사 중 하나에 실제로 부합하면 적절, 즐겨찾기는 하나 이상과 실제 주제가 이어지면 적절로 정한다. 여러 관심사를 모두 반영하는지는 별도 목록 지표다.
0과 U를 혼동하지 않는다. U를 제외한 점수만으로 전체 품질을 높게 보이게 하지 않는다.
채점 중 수정은 원래 답·변경 답·이유를 보존한다. U는 판단 근거가 추가되지 않으면 그대로 유지한다.
이번 결과는 1인 평가에 따른 프로젝트 적용 후보 선택이다. 독립 다인 평가·평가자 간 일치 검증 완료로 쓰지 않는다.

## 7. 지표와 통계

| 구분 | 지표·집계 |
| --- | --- |
| 주 지표 | 유효 추천 P@5: 1인 판정의 적절 수/5. 빈 슬롯과 U는 적절로 세지 않음 |
| 보조 | U 비율·판단 가능한 쌍만의 관련도·부적절 비율·반환 후보 수·빈 결과율 |
| 정보 품질 | 충분/부족 그룹의 위 지표를 별도 보고 |
| 관심사 균형 | 사람에게 확인한 관심 분야별 노출 수와 모든 관심 분야 노출 입력 수/n |
| 평가 진단 | LLM과의 0/1/U 교차표는 보조 진단. 평가자 간 일치는 측정 불가 |
| 운영 | 새 크리에이터당 분류 비용·배치 시간·호출 실패율·재시도·벡터 적재량·검색 p95 |

운영 지표는 같은 하드웨어·풀 규모·캐시 조건에서 측정하고 실제 청구액과 토큰 기반 추정 비용을 구분한다.
조회 지연은 오프라인 검색 시간과 서비스 API 응답 시간을 혼동하지 않는다.
입력 단위 같은 쌍 차이를 보고하고 공유 사용자/seed가 있으면 연결된 입력 묶음을 함께 재표집한다. 큰 연결 묶음이 생기면 표본 독립성을 다시 설계한다.
주 비교 5개(M3−M2, M4−M3, H3−M3, H4−M4, H4−H3)의 다중 비교를 고려한다. 경로별 유의한 비교만 골라 발표하지 않는다.
실행 시 통계 구현은 군집 재표집의 동시 신뢰구간 등 오류율 제어 방식으로 확정·검증한다. 기존 단순 95% 구간만으로 여러 후보의 우월성을 확정하지 않는다.
각 방법 평균·입력별 차이·표본 수·불확실성을 모두 기록한다. 경로 간 절대 점수를 직접 비교하거나 임의 비중으로 전체 점수 하나를 만들지 않는다.

## 8. 채택 규칙: 확정 전 제안

최소 의미 차이 δ=0.03, 허용 손실 ε=0.02는 논의를 위한 제안이다. 품질 하한과 월 비용·실패율·지연 상한은 아직 미확정이다.
허용값을 정하지 않은 상태에서 최종 평가 결과를 열지 않는다.

| 결과 | 선택 원칙 |
| --- | --- |
| 복잡한 방식이 δ 이상 개선, 조정 구간 하한>0, 운영 상한 통과 | 개선된 방식을 후보로 채택 |
| 단순한 방식의 손실 구간 상한이 ε 이하, 품질 하한·운영 상한 통과 | 비열등 근거로 단순한 방식 우선 |
| 차이 구간이 넓어 두 조건 모두 미충족 | 결론 유보. 운영 필요 시 기본 방식을 잠정 사용하고 잠정임을 표시 |
| 일부 그룹만 개선·정보 부족에서 문제 | 경로별 선택 또는 공통 정보 부족 대체 규칙 적용. 사전 규칙 밖 조합은 후속 개발 실험으로 이동 |
| 직접 입력·실제 이력 미확보 | 해당 경로의 서비스 채택 효과 결론 보류 |

구간에 0이 들어간다는 이유만으로 성능이 같다고 단정하지 않는다. M3를 제외하지 않으며 M2보다 추가 가치가 있는지도 판단한다.

## 14. 최종 사람 평가 결과와 선택

801쌍 전부 완료: 적절532·부적절269·U0. 채점 계약, 후보 hash, 쌍 목록, 답변별 근거 hash를 검증했다.
중복 제거 합집합의 적절532/801은 방식별 P@5가 아니다. 아래는 각 입력의 추천5명에서 적절한 비율을 평균한 값이다.

| 입력 | n | M2 | M3 | M4 | H3 | H4 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 일반 소개 | 75 | 0.736 | 0.755 | 0.827 | 0.749 | 0.835 |
| 짧은 소개 | 25 | 0.648 | 0.656 | 0.680 | 0.664 | 0.688 |

사전 고정한 그룹별 다중 비교 보정 99% paired bootstrap 구간:

| 비교 | 일반 소개 차이 [구간] | 짧은 소개 차이 [구간] |
| --- | --- | --- |
| M3−M2 | +0.019 [+0.003, +0.043] | +0.008 [0.000, +0.032] |
| M4−M3 | +0.072 [+0.024, +0.131] | +0.024 [−0.056, +0.120] |
| H3−M3 | −0.005 [−0.051, +0.035] | +0.008 [0.000, +0.032] |
| H4−M4 | +0.008 [−0.021, +0.037] | +0.008 [−0.032, +0.064] |
| H4−H3 | +0.085 [+0.027, +0.152] | +0.024 [−0.064, +0.168] |

**일반 소개는 M4를 잠정 선택한다.** M4−M3의 평균 개선은 기준0.03을 넘고 구간은0보다 크다.
다만 구간 하한0.024는0.03보다 작으므로 실제 개선이 반드시0.03 이상이라고 입증한 것은 아니다.
H4는 평균이 가장 높지만 M4 대비 추가 개선0.008은 기준 미달이며 구간도0을 포함한다. 세부 LLM 태깅의 추가 복잡성을 채택할 근거가 부족하다.
M3의 M2 대비 개선0.019도 기준에 못 미친다. H3의 M3 대비 개선은 확인되지 않았다.

**짧은 소개는 단순한 M2를 잠정 선택한다.** 사전 비교에서 평균 개선이0.03을 넘지 않고 차이도 불확실하다.
이는 모든 방법이 동등하거나 M2가 우월하다는 결론이 아니다. 표본25개로 차이를 확정하기 어렵다는 판단이다.
짧음은 기존 길이 기준이며 의미적 정보 충분/부족을 대신하지 않는다. 실제 서비스 분기 규칙과 정보 부족 대체 추천은 구현·검증 전이다.

서비스에 한 방식을 먼저 적용해야 한다면 일반 소개에서 근거가 있는 M4를 기본 후보로 삼되,
짧거나 정보가 부족한 소개의 처리와 비용·API 임베딩 정합성은 적용 단계에서 별도로 검증한다.
실제 선택 태그·즐겨찾기 개인화, 신규 채널 일반화, 서비스 전환 효과는 이번 결과로 확정하지 않는다.
1인 설계자 평가와 분야 균형 표본의 한계가 있으며 구간은 이 고정 풀의 입력 변동에 대한 조건부 불확실성이다.
