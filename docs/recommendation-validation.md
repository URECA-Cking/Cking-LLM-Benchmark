# 추천 흐름 실험 검증 및 일관성

## 검증 범위
2026-10-01 로컬 Python 가상환경에서 실행했다. API 호출 없는 단위 테스트와 저장 결과의 집계를 구분한다.

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m py_compile src/subtopic_tags.py src/hierarchy_eval.py src/hierarchy_judge.py
.venv/bin/python -m src.hierarchy_judge --flow-dir results/flow_v4 --baseline-dir results/flow_m234_v4 --output-dir results/hierarchy_v1
```

검증 대상은 원본 변경 거부, seed 제외, 판정 계약·텍스트 해시, 미채점 집계 거부, 원문 근거·부모 제한, 세부 미분류 폴백, 벡터/스칼라 보정 일치, 재개 시 중복 호출 방지다.
최종 테스트 실행 출력은 아래 최종 확인 절에 기록한다.
저장 판정 집계 출력: total=3709, cached=3709, new_calls=0, pending_pairs=0.
이는 캐시와 집계 재현 확인이며 새 API 반복 판정의 일관성 검증은 아니다.

## 고정 조건과 변경 조건
| 비교 | 고정 | 변경 | 해석 |
|---|---|---|---|
| 초기 흐름 → M234 | v4·원래 분할·임베딩 | 크리에이터 385→400, 즐겨찾기 집계 통일 | 초기 수치를 최근 수치와 직접 합치지 않음 |
| M234 → 계층 비교 | 468개 입력·후보 풀·상위 태그·기준선·경로별 판정 모델/질문 | 세부 주제와 보정 | 같은 입력에서 후속 탐색 비교 가능 |

계층 후보 생성 시 기존 M2/M3/M4 후보를 재계산해 이전 저장 결과와 대조한다.
단일 크리에이터와 태그/즐겨찾기는 질문이 다르므로 경로 간 절대 점수를 비교하지 않는다.
같은 텍스트·질문·모델·설정의 판정만 재사용한다.

## 해석 한계와 다음 검증
- v4 test 결과를 관찰한 뒤 세부 주제를 설계했다. 고정 분할이어도 새 확증 표본은 아니다.
- 주 H4 조건은 세부 일치 시 기존 가산점의 1.5배다. 증가를 세부 정보만의 효과로 단정하지 않는다. 총량 유지 조건도 함께 보고한다.
- H3 임계값 0.35/0.45/0.55와 가중치는 민감도이며 세부 정답으로 최적화하지 않았다.
- 초기 일부 세부 분류는 인용 생성 방식이 다르다. 원문 일치 검증은 같지만 단일 프롬프트 반복 실험은 아니다.
- 즐겨찾기는 그룹별 17개 합성 표본이다. 공유 seed·분야가 있어 독립 사용자 구간으로 해석하지 않는다.
- 실제 선택 태그·인기순·실제 즐겨찾기·사람 일치율은 미검증이다.
- 태깅과 판정은 같은 제공자 계열이므로 독립 사람 평가가 필요하다.

현재 결과를 탐색 결과로 동결하고, dev에서 조건을 확정한 뒤 보지 않은 새 표본으로 평가한다.
상위 태그만/세부 추가·총량 유지/세부 추가·가산점 증가를 구분하고 실제 입력과 블라인드 사람 평가를 추가한다.

## 재현 가능한 범위
코드·테스트·태그 정의·집계 결과 문서는 커밋한다. 원문·개별 라벨·판정·벡터는 results/에만 저장한다.
따라서 깨끗한 checkout에서 단위 테스트는 가능하지만 외부 v4 데이터와 캐시 없이 실험 수치를 독립 재현할 수 없다.
분류 4,205개와 신규 판정 908쌍의 실제 청구액은 미확인이다. 저장 토큰 수와 초기 실패 사용량 누락은 계층 결과 문서에 기록한다.
