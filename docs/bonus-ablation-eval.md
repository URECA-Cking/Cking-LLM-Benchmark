# 세부 태그 보정·가산점 조건 비교와 최종 검증 계획

## 이번 결론

상위 태그 가산점만 1.5배로 늘린 B는 468개 입력 모두에서 기존 A와 같은 추천 순위를 반환했다.
일반 소개글은 총량 유지 세부 보정 C도 개선됐다. 반면 즐겨찾기는 세부 보정과 가산점 증가를 함께 적용한 D에서만 평균이 상승했고 개선 구간은 0을 포함한다.
이는 현재 표본의 후속 탐색 결과이며 인과 효과·새 표본 성능·서비스 채택을 확정하지 않는다.

## 조건

| 조건 | 태그 | 최대 가산점 |
| --- | --- | ---: |
| A | 상위 M4 | 기존 |
| B | 상위 M4 | 기존의 1.5배 |
| C | 세부 H4 | 기존 |
| D | 세부 H4 | 기존의 1.5배 |

기존 v4·468개 입력·임베딩·텍스트·판정 질문/모델·seed별 보정 후 최대 집계를 유지한다.
B를 생성하고 A는 재계산 대조한다. C/D도 현재 소개글·상위/세부 태그·정의에서 재계산해 이전 결과와 대조한다. 판정만 계약·텍스트 해시 검증 후 재사용한다. 후보 합집합 2,651쌍 모두 기존 판정이 있어 신규 API 호출은 0건이다.
C/D는 세부 불일치의 보정도 줄이므로 같은 최대 가산점 비교는 세부 보정 규칙 전체의 비교다. D−B는 상위만 일치하는 후보의 보정 축소와 세부 일치 가산이 섞이며 순수한 가산점 증가 효과가 아니다.

A/B가 같은 순위였던 468개 중 413개는 상위 5명 모두의 점수가 동일하게 0.1씩 증가했다. 이 경우 후보 사이 순서를 바꾸지 못한다. 나머지 55개까지 동일 원인이라고 단정하지 않는다.

## 여러 관심 분야 노출 진단

후보의 LLM 상위 태그로 측정한 대리 지표이며 해당 태그를 사용하는 방법에 유리하다. 사람 품질·독립 정확도가 아니다.

| 조건 | 여러 분야 즐겨찾기에서 모든 입력 분야 노출 |
| --- | ---: |
| A_M4 | 7/17 (41.2%) |

| C_H4_equal | 9/17 (52.9%) |
| D_H4_x1.5 | 8/17 (47.1%) |

표본은 17개이며 C와 A의 차이는 입력 2개다. 구간 없는 탐색 진단으로 해석한다.

## 사람 점검 계획과 실행 범위

- 확대 점검 초안: 세부 태그 분야·소개 길이·미분류를 나눈 100개 채널의 의미적 태그 타당성 확인.
- 확대 실패 점검 초안: 방법 간 결과가 다른 입력을 포함한 60개에서 태그 오류·소개 부족·집계 문제를 확인.
- 진단용 표본이므로 전체 정확도를 추정하지 않는다. 실제 분류 점검 없이 근거 의미 타당성이 검증됐다고 기록하지 않는다.

## 최종 실험 설계 초안

1. M2·M3·M4·H3·H4를 유지한다. 개발용에서 가중치·임계값·태그 정의를 확정한다.
2. 이번까지 본 표본은 탐색으로 동결하고, 보지 않은 평가 표본에서 설정을 변경하지 않는다.
3. 입력 초안: 크리에이터 200(일반150·짧음50), 태그100, 즐겨찾기100. 실제 이력 확보와 변동성·채점 부담을 고려해 평가 전 수를 확정한다.
4. 2명의 독립 사람이 방법명을 숨긴 후보 합집합을 채점한다. 불일치는 원래 채점 기록을 보존하고 합의 절차로 처리한다.
5. 사람 P@5를 주 지표로, 무관 추천·분야 균형·태깅 비용/시간/실패율을 함께 비교한다. 공유 사용자/seed는 묶어서 재표집한다.
6. 최소 의미 차이 P@5 +0.03은 제안값이다. 비용 허용값·채택 규칙·사람 판정 기준은 결과를 보기 전에 팀이 확정해야 한다.
7. 차이가 불명확하면 더 단순한 방법을 우선한다. 경로별 선택을 허용한다. 실제 선택 태그·즐겨찾기 없는 경로는 서비스 효과 결론을 보류한다.

## 직접 수행한 소규모 점검

사용자 1명이 터미널에서 세부 태그 20개와 추천 20쌍을 모두 판정했다. 저장된 표본 계약과 각 항목의 evidence_hash를 현재 입력과 대조했다.

| 점검 | 적절 | 부적절 | 판단 어려움 |
| --- | ---: | ---: | ---: |
| 태그 묶음 20개 | 15 | 5 | 0 |
| 추천 쌍 20개 | 10 | 10 | 0 |

추천 표본 구성은 크리에이터 16·즐겨찾기 3·태그 1쌍이다. 기존 LLM 판정과 16/20쌍 일치했다.
이는 네 방법의 후보 합집합에서 뽑은 진단 표본이며, 10/20은 H4 단독 P@5가 아니다. 75%·80%를 전체 태그 정확도·사람 일치율 게이트로 일반화하지 않는다.
태그는 묶음 단위 판정이다. 부적절 5건에는 의미적 오분류뿐 아니라 세분화 필요성·주된 활동 기준에 관한 판단이 섞여 있다.
정보가 부족한 소개글의 이메일·광고 링크·막연한 문구로 연결된 부적절 사례가 관찰됐다. 원인 가설이며 정보 부족 처리의 개선 효과는 미검증이다.
최종 선정 전에 충분/부족 입력을 구분하고 직접 선택 태그 또는 인기순 대체의 효과를 별도로 검증해야 한다.

### 터미널 점검 실행

```bash
.venv/bin/python -m src.human_check_cli tags --data-dir ~/Desktop/youtube-collect/gold_variants/v4
.venv/bin/python -m src.human_check_cli recommendations
```
각 모드는 고정 시드 진단 표본 20개를 사용한다. `--limit`으로 수량을 바꿀 수 있다.
`1` 적절, `0` 부적절, `u` 판단 어려움, `s` 건너뛰기, `q` 종료. 이유 메모와 답변을 즉시 저장하며 같은 명령으로 재개한다.
판단 어려움은 null로 저장하며 부적절 0과 구분한다. 추천 점검에서는 방법명·LLM 점수를 숨긴다.
소개글·개별 사람 판정은 results/ 안에만 보관한다. 이 점검 도구는 API를 호출하지 않는다.
