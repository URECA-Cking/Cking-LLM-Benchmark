# 당시 선택과 한계

[기록 목차](index.md)

## 결론

**요약**

1. 임베딩 모델은 **`bge-m3`**, 방식은 **M4 또는 M3**를 1순위 후보로 제안한다. 확정 채택은 아니다.
2. 확정하지 못하는 이유: 태그 보정이 M2(순수 임베딩)보다 관련도를 **0.1 이상** 올려야 채택한다는 사전 기준을 어느 설정도 넘지 못했다. `bge-m3` M4가 +0.094로 가장 근접했다.
3. 대안은 **`KURE-v1` M2**(태그 보정 없이도 견고)와 **`bge-m3` M3**(외부 LLM 불필요, 재현성 좋음)다.
4. **서버는 로컬 모델 대신 DeepInfra API의 같은 bge-m3로 진행한다.** 조건은 임베딩을 저장해 쓰고, tau·bonus·컷오프를 API 벡터로 다시 고른 값으로 두는 것이다(아래 "결정").

**M3와 M4 중 무엇을 고를까**

| 판단 기준 | 결과 | 근거 |
| --- | --- | --- |
| **사전 판단 기준** (M4가 M3보다 관련도가 0.1 이상 높지 않으면 M3) | **M3** | `bge-m3`에서 M4 − M3 = +0.040으로 기준(0.1) 미달 |
| **점 추정치 선호** | M4 | 관련도 0.487 대 0.447 |

**무엇을 우선하느냐에 따른 선택**

| 우선하는 것 | 선택 | 감수할 점 |
| --- | --- | --- |
| 관련도 | `bge-m3` + M4 | 운영 중에도 LLM 태깅(비용·지연·장애 대응)을 유지해야 하고, 실행마다 결과가 조금씩 달라짐 |
| 재현성, 외부 LLM 없이 운영 | `bge-m3` + M3 | 관련도가 M4보다 근소하게 낮음(0.447 대 0.487) |
| 가장 단순한 파이프라인 | `KURE-v1` + M2 | 관련도가 더 낮음(0.420), 소개 부족 사례(④)에서 X08·X10 실패 |

### 용어 정리

**추천 방식**

| 기호 | 뜻 |
| --- | --- |
| **M1** | 태깅(zero-shot) 단독. 태그를 붙인 뒤 공유 태그 Jaccard(겹치는 정도)로 비교 |
| **M2** | 임베딩 단독. 소개글 벡터의 코사인 유사도 |
| **M3** | M2 + zero-shot 태그가 겹치면 가산점(bonus). 외부 LLM 불필요 |
| **M4** | M2 + LLM이 붙인 태그가 겹치면 가산점(bonus) |
| **M5** | `bge-m3` M2 상위 20명을 `bge-reranker-v2-m3`로 다시 채점·정렬 |
| **R1·R2** | 참고용. 사람이 입력한 분야를 쓰므로 실제보다 유리한 상한선 |

**평가와 지표**

| 기호 | 뜻 |
| --- | --- |
| **E1** | zero-shot 태깅 정확도. Top-1은 1순위 태그가 정답인 비율, Top-3 포함률은 상위 3개 안에 정답이 있는 비율 |
| **E2** | 추천 관련도. 쿼리 30명의 상위 5명을 LLM이 0/1/2점으로 판정 |
| **E3** | 어려운 대표 사례 통과 여부(아래 사례 표) |
| **E4** | 운영 지표(비용·시간·메모리) |
| nDCG | 순위까지 고려한 관련도(높을수록 좋음) |
| 무관비율 | 상위 5명 중 무관하다고 판정된 비율(낮을수록 좋음) |
| tau | zero-shot 태그를 붙이는 기준값. 모델별로 dev에서 선택 |
| bonus | 태그가 겹칠 때 더하는 가산점. 방식별로 dev에서 선택 |
| 컷오프 | 유사도 점수가 이 값보다 낮은 후보를 추천에서 빼는 기준 |

**E3 대표 사례** (합성 데이터에 일부러 넣은 어려운 크리에이터. 표의 X01·K07 등은 크리에이터 ID)

| 번호 | 무엇을 보나 | 대표 사례 |
| --- | --- | --- |
| ① 동의어 | 단어가 달라도 같은 뜻이면 비슷하다고 보는가 | F01 홈트 ↔ F02 맨몸운동, X12(대식가, "먹방" 단어 없음) ↔ K03 먹방, X13 데일리룩 ↔ S01 |
| ② 경품 잡음 | 소개글의 경품 문구에 끌려 무관한 크리에이터가 추천되지 않는가 | X01 파스타공방("닌텐도 스위치 증정"), X02 스쿼트요정("플스5 추첨") |
| ③ 분야 넘기 | 분야가 달라도 실제로 비슷한 크리에이터를 찾는가 | X14 푸드 여행 → K07 맛집(요리 분야), X15 웨어러블 → F06 |
| ④ 소개 부족 | 정보가 거의 없는 입력에서 엉뚱한 추천을 하지 않는가 | X08("안녕하세요"), X10(이벤트 제목만) |

①~③은 7건, ④는 2건이라 전체 9건이다. ④는 컷오프 실험(이슈 #10)에서 추가됐다.

### 채택하지 않은 이유

| 대상 | 이유 |
| --- | --- |
| `Qwen3-Embedding-0.6B` | 관련도는 높지만(M4 0.473) E1·E3에서 한 단계 약함. 쿼리 프롬프트 재측정 후 E3 M4가 5/7 → 6/7로 올랐지만 X14→K07 "분야 넘기"는 여전히 못 풂 |
| `text-embedding-3-small` | 태깅 Top-1 0.729로 가장 낮고 X14→K07을 못 풂. bge-m3와 관련도 차이가 0.05를 넘어 품질 기준으로 bge-m3 우위 |
| M5 (`bge-m3` M2 + 리랭커) | nDCG는 전체 최고(0.553)지만 경품잡음(X01·X02) 둘 다 실패. **관련도를 높이는 것과 잡음에 강한 것은 다른 문제** |

### M3 vs M4: 재현성

캐시 무효화를 고치면서 LLM 태깅을 두 번 다시 돌렸더니 결과가 달라졌다.

- **M4:** 두 번째 실행에서 `M4_openai`·`M4_qwen3`가 X02 경품잡음에 새로 걸렸다. `M4_bge-m3`만 두 번 다 통과했다. LLM 응답이 실행마다 조금씩 달라져 E3 통과 여부가 흔들린다.
- **M3:** 임베딩만으로 결정돼 `bge-m3`·`KURE-v1`에서 두 번 다 7/7로 안정적이었다.
- **정리:** 관련도만 보면 M4가 근소 우위다. **재현성을 중요하게 본다면 M3가 더 신뢰할 수 있는 선택**이다.

### 운영 조건과 과제 범위

- **서버 메모리:** 모델 하나 기준 CPU에서 약 1.9~2.3GiB, M5(bge-m3 + 리랭커)를 함께 올리면 약 3.8GiB (아래 "로컬 모델 메모리 사용량")
  - **서버는 로컬 bge-m3 대신 API(DeepInfra `BAAI/bge-m3`)로 진행한다.** 벡터·유사도는 로컬과 사실상 같다(유사도 최대 차이 0.0004~0.0006). 다만 로컬에서 고른 tau·bonus·컷오프를 그대로 쓰면 경계에 놓인 크리에이터 몇 명의 태그·후보가 달라져, **API 벡터로 파라미터를 다시 고르고 임베딩은 저장해서 쓴다** (아래 "로컬 ↔ API bge-m3 동등성")
- **취향 요약문 → 크리에이터 탐색**(서비스 쿼리 형식이 확정되기 전의 탐색):
  - M4가 로컬 임베딩 3종 모두에서 가장 높았다. M4 > M3 > M2 전체 순위는 bge-m3·KURE-v1만 두 평가에서 같고, Qwen3는 M2·M3 순서가 다르다.
  - Qwen3가 약하지 않았고, bge-m3·KURE-v1 M2 단독은 쿼리가 길어질수록 흔들렸다 (아래 "사용자 취향 쿼리 검증").
  - 형식이 정해지면 다시 확인한다("남은 과제").
- **한계:** 모든 수치는 100명 합성 데이터의 경향이며 실제 운영 규모 재검증 전까지 확정 성능이 아니다.

## 사전 판단 기준 대비 결과

실험 계획 단계에서 정해 둔 판단 기준(제안값)을 결과 표에 그대로 적용한 것이다. 관련도는 E2 점 추정치이고, 설정 간 차이는 쿼리별 짝 차이 신뢰구간이 0을 포함하는 경우가 많다(위 "방식 간 차이"). 그래서 아래 판정은 점 추정 기준의 참고용이다.

| 질문 | 기준 | 결과 | 판정 |
| --- | --- | --- | --- |
| 보정(M3/M4) 채택 | 관련도가 M2보다 **0.1 이상** 높고 경품잡음 사례(②) 통과 | openai M4 +0.113이지만 X02 실패. bge-m3 M3 +0.054·M4 **+0.094**(근소 미달), KURE-v1 M3 +0.040·M4 +0.047, Qwen3 M3 −0.027·M4 +0.066 | **기준을 충족한 설정 없음**. bge-m3 M4가 가장 근접 |
| zero-shot(M3) vs LLM(M4) 태그 | M4가 M3보다 0.1 이상 낫지 않으면 **M3** | bge-m3 +0.040, KURE-v1 +0.007, Qwen3 +0.093, openai +0.133(단 ② 실패) | openai 외 세 모델은 **M3**. 재태깅 재현성도 M3가 더 안정적 |
| bge-m3 vs text-embedding-3-small | 차이 0.05 이내면 운영 조건, 이상이면 품질 우선 | M2 +0.106, M3 +0.180, M4 +0.087 (bge-m3 우위) | **품질 우선 → bge-m3** |
| bge-m3 vs KURE-v1 (추가 비교) | 위와 같음 | M2 KURE-v1 +0.027, M3 +0.013, M4 bge-m3 +0.020 | 0.05 이내 → **운영 조건으로 결정**. KURE-v1은 M2만으로 E3 ①~③ 7/7(④까지 전체 7/9) |
| zero-shot 태깅 사용 가능 | Top-3 포함률 **80% 이상** | openai 0.886, bge-m3 1.000, KURE-v1 1.000, Qwen3 0.986 | **4개 모델 모두 충족** |
| 전부 기대 이하 | R2(입력 분야 보정)로 가고 자동 태깅 제외 | R2_bge-m3 0.447, M4_bge-m3 0.487, M3_bge-m3 0.447 (R2는 정답 분야를 쓰는 상한선 참고치) | **해당 없음** — 자동 태그가 R2 수준 이상 |

**해석**
- 엄격하게 적용하면 "태그 보정을 무조건 채택할 만큼의 개선(+0.1)"은 어느 설정도 넘지 못했다.
- 그래서 이 문서는 bge-m3 + M4를 확정이 아닌 **1순위 후보**로만 제안한다.
- 보정 없이도 경품잡음에 견고한 KURE-v1 M2와 외부 LLM 없이 쓸 수 있는 M3를 대안으로 함께 남긴다.
- 어느 쪽이든 100명 규모 합성 데이터의 경향이며 확정 성능이 아니다.

## 선택 이유와 한계

### 선택 이유

수치 근거는 위 E1~E3와 "사전 판단 기준 대비 결과" 표에 있고, 여기서는 후보별 판단만 정리한다.

- **`bge-m3` + M4 (1순위 후보)**
  - E2 관련도 점 추정치가 단독 1위(0.487)다. 다만 Qwen3+M4(0.473)·KURE-v1+M4(0.467)·M5_bge-m3(0.460)와의 쿼리별 짝 차이 신뢰구간이 모두 0을 포함해 우위를 확인하지는 못했다(위 "방식 간 차이").
  - 재태깅 재현 실험에서 `M4_bge-m3`만 두 번 다 경품잡음 E3를 통과해, 상위권 중에서는 가장 안정적이었다.
- **`KURE-v1` + M2 (대안)**
  - E1 Top-1 1위(0.914)이고, 태그 보정 없이 E3 ①~③ 7종을 전부 통과했다(④까지 9건으로는 7/9).
  - 보정이 필요 없으니 LLM 의존(비용·지연·장애 대응)이 사라져 파이프라인이 단순해진다. 대신 관련도가 낮다(M2_kure-v1 0.420 대 M4_bge-m3 0.487).
- **`bge-m3` + M3 (대안)**
  - `bge-m3`는 M3·M4가 E3 ①~③에서 동률(7/7)이고(④까지 9건으로는 각각 8/9), E2 M4 − M3 짝 차이의 신뢰구간도 0을 포함한다(bge-m3 [−0.007, +0.093], KURE-v1 [−0.033, +0.053]). KURE-v1은 M3 7/7·M4 6/7(9건으로는 둘 다 7/9)이다.

- **dev 규모:** dev 30명으로 고른 tau·bonus의 민감도는 합성 300명으로 확인했다(아래 "dev 규모 민감도"). 다만 합성 데이터가 한 LLM이 쓴 균일한 문체라 실제 운영 규모(수백~수천 명)의 다양성까지 검증한 것은 아니다.
- **소개글 작성:** 100명 중 86명은 LLM이 초안을 쓰고 14명만 직접 작성해, 문체가 실제 사용자 입력보다 균일할 수 있다.
- **M5의 구조적 한계:** M2가 이미 추린 상위 20명만 재정렬한다. 리랭커가 M2의 오답(경품잡음으로 끌려온 후보 포함)을 상위권으로 더 끌어올릴 수는 있어도, M2가 애초에 놓친 후보를 새로 찾아오지는 못한다.
- **소개글 결과가 취향 쿼리에 그대로 옮겨지지는 않는다:**
  - 서비스의 쿼리 형식이 아직 정해지지 않아 "취향을 요약한 문장"을 가정해 별도로 확인했다(위 "사용자 취향 쿼리 검증" 절).
